# 테스트 전략

## 목적

"뭘 자동 테스트로, 뭘 수동 QA로 확인할지" 명확한 기준을 제공한다.

## 자동 테스트 대상 (코드로 작성)

| 대상 | 테스트 종류 |
|------|------------|
| 비즈니스 로직 계산 | 단위 테스트 |
| 상태 전이 | 단위 테스트 |
| API 응답 형식/상태코드 | 통합 테스트 |
| 입력 검증 (유효/무효) | 단위 테스트 |
| DB 쿼리 결과 | 통합 테스트 |
| 인증/인가 | 통합 테스트 |

## 수동 QA 대상 (체크리스트로 확인)

| 대상 | 확인 방법 |
|------|-----------|
| UI 레이아웃/시각적 확인 | 브라우저에서 눈으로 |
| 사용자 흐름 (여러 화면 시나리오) | 시나리오 따라 조작 |
| 외부 시스템 연동 | 실제 환경 테스트 |
| 모바일 실기기 확인 | 실기기 조작 |
| 반응형 레이아웃 | 브라우저 리사이즈 |
| 접근성 | 키보드/도구 확인 |

## 우선순위 판단 기준

| 조건 | 자동 테스트 | 수동 QA |
|------|------------|---------|
| 돈이 오가는 기능 | ✅ 필수 | ✅ 필수 |
| 핵심 사용자 흐름 | ✅ 권장 | ✅ 필수 |
| 일반 CRUD | ⚡ 있으면 좋음 | ✅ 기능 변경 시 |
| 보조 기능 | ❌ 생략 가능 | ⚡ 대규모 변경 시만 |

## 테스트 작성 시점

| 시점 | 행동 |
|------|------|
| 새 기능 구현 완료 시 | 자동: 핵심 로직 단위 테스트. QA: 체크리스트 생성 |
| 버그 수정 완료 시 | 자동: 해당 버그 재현 테스트 추가. QA: regression 마킹 |
| 리팩토링 완료 시 | 자동: 기존 테스트 통과 확인만. QA: 불필요 |
| 비즈니스 규칙 변경 시 | 자동: 관련 단위 테스트 수정. QA: 영향받는 체크리스트 갱신 |
