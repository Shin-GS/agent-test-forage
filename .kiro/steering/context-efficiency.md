# 컨텍스트 효율 관리 규칙

## 파일 읽기 규칙
- 변경 대상 파일과 직접 관련된 파일은 자유롭게 읽는다
- 목적 없는 탐색적 읽기가 10개 이상 필요하면 서브에이전트에 위임
- 대형 파일(500줄+)은 필요한 라인 범위만 지정
- 같은 파일을 2회 이상 읽지 않는다

## 서브에이전트 프롬프트 규칙
- 프롬프트 500자 이내 권장, 1000자 초과 금지
- contextFiles로 경로만 전달, 인라인 코드 블록 금지
- 전체 코드를 프롬프트에 복사하지 않는다

## 서브에이전트 결과 처리
- raw output 전체를 그대로 전달하지 않는다
- 핵심 결론/피드백만 구조화하여 전달
- 수용할 내용: "변경 파일 목록 + 핵심 요약 (3줄 이내)"

## 연쇄 호출 규칙
- 서브에이전트 연쇄 호출은 3단계까지 허용
- 3단계 초과 시: 중간 결과 요약 + 사용자에게 진행 상황 보고
- 병렬 호출 가능한 에이전트는 반드시 병렬로 호출
- 같은 에이전트를 같은 작업으로 2회 이상 호출하지 않는다

## Tool 결과 처리
- JSON, HTML, 로그 등 raw payload를 그대로 전달하지 않는다
- 필요한 필드/섹션만 추출하여 전달

## 품질 보호 규칙
- 압축 시 ID, 날짜/시각, 상태값, 에러 코드/메시지, 정책 조건은 원문 그대로 보존
- 사실 정확성이 훼손되는 압축은 금지

## 대규모 작업 판단 기준
- 서브에이전트 호출 3회 이상 예상
- 변경 대상 파일 10개 이상
- FE + BE 동시 변경
- 새 화면/기능 추가
