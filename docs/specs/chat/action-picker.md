# 액션 피커

## 개요

채팅 input 영역에 겹쳐 노출되는 구조화된 입력 UI. AI가 레시피 실행에 필요한 데이터를 수집할 때 또는 실행 중 사용자 입력이 필요할 때 표시.

## 동작 규칙

- 액션 피커가 뜨면 채팅 input 비활성화 (자유 타이핑 불가)
- 모든 형태(버튼형/단일 필드/다중 필드)가 액션 피커 위치에 통일 노출
- 취소 클릭 → AI "취소되었습니다" 응답 → 레시피 전체 중단 → 채팅 input 복귀
- 사용자가 채팅 API로 직접 메시지를 보내면 → 액션 피커 자동 닫힘 (취소와 동일 처리)
- 취소 버튼 상시 노출

## 형태

### 버튼형

2~4개 선택지만 있을 때:

```
┌─────────────────────────────────────────┐
│ 어떤 모드로 실행할까요?            [✕]  │
│                                         │
│ [자동 실행] [직접 입력하며 실행]          │
└─────────────────────────────────────────┘
```

### 단일 필드형

1개만 입력/선택:

```
┌─────────────────────────────────────────┐
│ 공고를 선택해주세요               [✕]   │
│ 🔍 [______________]                     │
│   네이버 백엔드 (3년차)                  │
│   네이버 백엔드 시니어                   │
│              [취소]  [선택 완료]         │
└─────────────────────────────────────────┘
```

### 다중 필드형

2개 이상 입력:

```
┌─────────────────────────────────────────┐
│ 지원 정보 입력                    [✕]   │
│                                         │
│ 지원 유형 *                             │
│ (● 정규직  ○ 계약직  ○ 인턴)            │
│                                         │
│ 희망 연봉                               │
│ [___5000___] 만원                       │
│                                         │
│              [취소]  [확인]              │
└─────────────────────────────────────────┘
```

- 필드 5개 이상 시: max-height 제한 (화면 50% 이하) + 내부 스크롤
- 하나의 사용자 입력 스텝의 모든 필드를 한 화면에 표시 (다단계 아님)

## 응답 처리

### 별도 API

액션 피커 입력 완료 → 일반 메시지 API가 아닌 별도 API로 구조화된 값 전송:

```
POST /api/v1/action-picker/respond
{
  "executionId": 456,
  "stepIndex": 3,
  "values": {
    "jobPostingId": "123",
    "applicationType": "정규직"
  }
}
```

### 채팅 표시

입력 완료 후 채팅에는 사용자가 입력한 값을 요약 텍스트로 표시:

```
┌─────────────────────────────┐
│ 📝 입력 완료                  │
│ 지원 유형: 정규직             │
│ 공고: 네이버 백엔드 (3년차)   │
└─────────────────────────────┘
```

## 정적 필드 원칙

액션 피커 내부의 필드 구성은 항상 정적. 필드 간 동적 의존 관계 없음.

| 허용 | 비허용 |
|------|--------|
| 스텝 스킵 (condition) | 필드 구성 동적 변경 |
| select 옵션을 이전 API 결과에서 채움 (optionsFrom) | 이전 입력에 따라 필드 수 변경 |
| 필드별 기본값 설정 | 필드 A 선택에 따라 필드 B 옵션 변경 |

동적 의존이 필요한 경우 → 스텝을 분리하여 condition으로 처리.

## 필드 타입

| 필드 타입 | 설명 | 예시 |
|-----------|------|------|
| `text` | 단일 텍스트 | 상품명, 이메일 |
| `number` | 숫자 | 수량, 금액 |
| `textarea` | 여러 줄 텍스트 | 메모, 설명 |
| `select` | 단일 선택 | 카테고리, 상태값 |
| `multi-select` | 복수 선택 | 태그, 옵션 |
| `radio` | 라디오 | 2~4개 선택지 |
| `checkbox` | 체크박스 | 동의, on/off |
| `date` | 날짜 선택 | 시작일, 종료일 |
| `search-select` | 검색형 선택 (대량 옵션) | 공고 검색, 상품 검색 |
| `json` | JSON 에디터 | 복잡한 구조 직접 입력 |

## 변수 정의 스키마

레시피의 사용자 입력 스텝에서 정의하며, 실행 시 액션 피커로 렌더링됨:

```json
{
  "variables": [
    {
      "key": "productId",
      "label": "상품 ID",
      "type": "text",
      "required": true,
      "placeholder": "상품 ID를 입력하세요"
    },
    {
      "key": "quantity",
      "label": "수량",
      "type": "number",
      "required": true,
      "default": 1,
      "min": 1,
      "max": 100
    },
    {
      "key": "category",
      "label": "카테고리",
      "type": "select",
      "required": true,
      "options": [
        { "label": "식품", "value": "food" },
        { "label": "전자기기", "value": "electronics" }
      ]
    }
  ]
}
```

## search-select 상세

대량 옵션(수천 개 이상)을 처리하기 위한 검색형 선택:

- 사용자 타이핑 → debounce 후 서버 검색
- 필터링된 결과 노출 → 선택
- `optionsFrom` 필드로 이전 스텝 결과를 데이터 소스로 지정 가능
