# 채팅 인터페이스 구조

## 레이아웃 (ChatGPT 스타일)

기존 상단 가로 탭 네비게이션(채팅/서브도메인/레시피/설정)은 폐지하고, **모든 네비게이션을 좌측 사이드바 상단으로 통합**한다.

```
┌───────────────────┬──────────────────────────┬───────────────────────────┐
│ 사이드바            │   대화 영역 (중앙)         │   사이드 패널 (우)          │
│ [로고  ⟨접기]      │                          │                           │
│ [+ 새 채팅]        │  사용자 ↔ AI 대화         │  홈 / 레시피 / 히스토리     │
│ [메뉴: 레시피·설정] │  + 카드 UI              │  → 상세 보기 (스택)        │
│ ─ 고정 ───────────│  + 액션 피커 (input 위치)  │  (접기/리사이즈 지원)      │
│ [대화 기록 (스크롤)] │                          │                           │
└───────────────────┴──────────────────────────┴───────────────────────────┘
```

### 사이드바 구성

위에서부터 아래 순서로 배치한다. **상단(로고~메뉴)은 고정이고, 대화 목록만 스크롤**된다.

1. **[로고 + 접기 버튼]** — 최상단. 접기 버튼(⟨)으로 아이콘 레일로 축소
2. **[+ 새 채팅]** — 새 대화 시작 (빈 대화방은 서버에 만들지 않음, 화면 전환만 — 아래 빈 대화 처리)
3. **[메뉴]** — 레시피 관리 · 설정 등 별도 페이지 라우트 이동 (기존 상단 탭이 하던 역할 흡수)
4. **[대화 기록 목록]** — 이 영역만 세로 스크롤. 나머지는 스크롤에 밀리지 않고 고정

### 사이드바 접기/펼치기 (아이콘 레일)

- 펼침 (기본, Desktop): 대화 목록 + 메뉴 + 새 채팅 전체 표시
- 접힘: **아이콘 레일**로 축소 — 펼치기 아이콘 + [+ 새 채팅] 아이콘만 세로로 표시 (검색 기능은 없으므로 검색 아이콘 미포함)
- **레일(접힘) 상태에서는 레시피 관리/설정 등 메뉴에 직접 진입할 수 없다 — 먼저 사이드바를 펼쳐야 접근**한다 (레일에 노출되는 것은 펼치기 아이콘 + [+ 새 채팅]뿐)
- 토글 버튼: 사이드바 최상단 로고 옆
- localStorage에 접힘/펼침 상태 저장

### 패널 리사이즈 / 접기

- 좌측 사이드바: 펼침/접힘(아이콘 레일) 2단계. 폭 리사이즈는 하지 않음
- 우측 사이드 패널: 좌측 경계선 드래그로 리사이즈(최소/최대 폭 clamp) + 완전 접기 지원. 상세는 [panel/overview.md](../panel/overview.md#접기--리사이즈-1차)
- localStorage에 상태/너비 저장

### 반응형 자동 접기

- **중앙 채팅 영역의 최소 폭 480px를 항상 보장**한다 (양쪽이 채팅을 침범하지 않음)
- 뷰포트 폭 **< 1200px**이면 **우측 패널이 먼저** 자동 접힘/오버레이로 전환
- 뷰포트 폭 **< 768px**이면 **좌측 사이드바도** 아이콘 레일 또는 오버레이로 전환
- 우선순위: **우측 먼저, 그다음 좌측**
- (임계값 px는 구현 시 미세조정 가능)

### 테마

- **라이트 테마 기본** (장시간 사용 피로감 개선). 색상은 모두 tokens 변수 기반 — 하드코딩 없음
- 다크/라이트 토글은 백로그. 구조는 `data-theme` 속성으로 확장 여지만 남겨둔다(현재는 light 고정)

## 사용자 입력 수단

- **채팅 Input** — 자유 텍스트 입력
- **액션 피커** — 구조화된 입력 (input 영역에 겹쳐 노출). 상세: [action-picker.md](action-picker.md)

## 대화 관리

- 대화방 생성/삭제 가능
- 하나의 대화에서 여러 레시피를 연속 실행 가능
- 대화방 삭제 시 작업 히스토리는 독립적으로 유지
- 한 대화방에서 동시에 여러 요청 불가 (대화방 단위 락). 다른 대화방은 독립적으로 사용 가능.

### 대화 이름

대화방은 **첫 메시지 전송 시점에 서버에서 생성**되며(빈 대화방을 미리 만들지 않음), 이름은 아래 단계로 정해진다.

1. **임시 제목 (첫 메시지 시, 즉시)**: AI 요약 전이라, 첫 메시지 내용 앞부분을 잘라 임시 제목으로 세팅 (20자 이내, 초과 시 말줄임). 목록에 곧바로 표시되게 함
2. **요약 제목 (AI 응답 후, 교체)**: fast 모델이 첫 대화를 요약해 제목을 교체 → `session_list_update`로 목록 갱신 (ai-config.md)
3. **레시피로 시작한 경우**: 요약 대신 레시피명으로 제목 세팅 (FE가 title 지정)
4. 사용자가 언제든 이름 변경 가능

### 빈 대화 처리

- **빈 대화방은 서버에 생성되지 않는다.** "새 대화"는 FE 화면 전환일 뿐이고, 첫 메시지를 전송해야 서버에 대화방+메시지가 함께 생성된다
- 따라서 메시지를 안 보내고 나가면 서버에 아무것도 남지 않음 (orphan 대화방 원천 차단)
- API: 방 없이 첫 메시지 전송 → 대화방 생성 겸함. 이후 메시지는 대화방 ID로 전송 (messaging.md)

### 대화 목록 정렬 / 최상단 이동

- **정렬 기준은 `lastMessageAt` (내림차순)으로 통일**한다. 목록의 순서는 오직 이 값으로 결정한다
- **최상단으로 이동하는 경우** (`lastMessageAt` 갱신): 새 메시지(내 전송이든 AI/상대발이든)로 `lastMessageAt`이 갱신되면 최상단으로 이동
  - 사용자가 메시지를 전송할 때
  - AI/상대발 새 메시지를 수신했을 때
  - 레시피 실행이 완료됐을 때
- **이동하지 않는 경우**:
  - 읽음 처리(대화방 클릭/진입)만으로는 순서가 바뀌지 않음 — 읽음은 unread 뱃지만 해제
  - 에러/실행 중에는 이동하지 않음

### AI 응답 중 로딩

- 채팅 영역에 "..." 로딩 인디케이터 표시 (AI가 tool 선택 중)
- 완성된 응답이 오면 로딩 인디케이터가 실제 메시지로 교체
- 빈 메시지: FE 전송 버튼 비활성화 + BE API 400 반환 (이중 방어)

## 대화방 서비스 설정

대화방에 "대상 서비스"를 설정하면 해당 서비스의 레시피를 우선 매칭.

### 설정 방법
- **AI가 자동 설정**: 서비스 미지정 상태에서 레시피 실행 시, AI가 "어느 서비스에서 진행할까요?" 질문 → 사용자 선택 → 해당 서비스로 대화방 자동 설정
- **사용자가 직접 변경**: 채팅 헤더의 [변경] 클릭

### 서비스 미지정 시 AI 동작

| 상황 | AI 동작 |
|------|---------|
| 레시피 1개 매칭 (서비스 명확) | "이 서비스(XX) 맞나요?" 확인 후 설정 |
| 여러 서비스에 같은 레시피 | 서비스 선택 버튼 제시 → 선택 시 자동 설정 |
| 현재 서비스에서 못 찾음 | "다른 서비스에서 찾기" or "레시피 생성 요청" 제안 |
| 다른 서비스의 레시피로 매칭됨 | "XX 서비스의 레시피인 것 같은데, 서비스를 변경할까요?" |

### 헤더 표시

```
┌──────────────────────────────────────────┐
│ 회원가입 테스트        🏷️ 사람인  [변경]  │
└──────────────────────────────────────────┘
```

## 대화방 목록 상태

사이드바 대화 목록에 태그 + 상태 뱃지 표시:

```
회원가입 테스트 [사람인] 🔄
입사지원 테스트 [사람인] 🟡
공고 등록       [잡코리아] 🔵
잡담
```

| 상태 | 표시 | 조건 (session_status 매핑) | 우선순위 |
|------|------|------|---------|
| **입력 대기** | 🟡 | `input_waiting` (레시피가 사용자 입력 기다리는 중) | 1 (최고) |
| **처리 중** | 🔄 | `ai_responding` 또는 `executing` (둘 다 🔄로 통합) | 2 |
| **안 읽음** | 🔵 | 내가 안 본 사이에 새 메시지 생김 | 3 |
| **유휴** | (없음) | `idle` (작업 없음, 마지막 메시지 확인함) | 4 |

- 상태가 겹칠 때 우선순위 높은 것 하나만 표시
- 읽음 처리: 대화방 진입(클릭) 시 안 읽음 → 유휴
- **입력 영역은 `ai_responding`/`executing`을 구분해 다른 문구를 표시**(messaging.md)하지만, **목록 뱃지는 둘을 🔄 하나로 통합**한다 (목록에선 "처리 중" 여부만 필요)

### 서비스 배지 표시

- 각 대화 항목에 **활성 서비스 배지(serviceName)**를 표시한다 (위 예시의 `[사람인]` `[잡코리아]`)
- 배지 텍스트는 대화방 목록 응답의 `serviceName`을 사용한다 (BE 계약: [messaging.md `session_list_update`](../common/messaging.md#대화방-목록-갱신-session_list_update))
- **`serviceName`이 null(미지정)이면 배지 없음** (messaging.md 계약: 서비스 미지정 시 null)

## 대화 항목 조작 (더보기 메뉴)

대화 항목에 hover하면 **더보기(⋮) 버튼**이 나타난다. 클릭 시 메뉴로 **이름 변경 / 삭제**를 제공한다.

### 이름 인라인 편집 (ChatGPT식)

- 더보기 → [이름 변경] 선택 시, **항목이 인풋으로 전환**되고 기존 텍스트가 **전체 선택**된 상태로 포커스
- 저장: **Enter** 또는 **blur(포커스 해제)**
- 취소: **ESC** (원래 이름으로 롤백)
- 유효성 (FE·BE 동일 검증):
  - 트림 후 **빈 값이면 롤백**(변경 없음)
  - 길이 **1~50자** (초과 시 잘라내거나 거부)
  - **제어문자(개행/탭 등) 제거**
  - 그 외 특수문자는 허용
- **표시는 escape로 XSS 방지** (입력 자체를 제한하지 않고, 렌더 시 이스케이프)

### 삭제 (커스텀 확인 모달)

- 브라우저 기본 `confirm()` **사용 금지**
- 재사용 컴포넌트 **ConfirmModal** 사용:
  - 제목 + 설명 + [취소] / [삭제] 버튼
  - 위험 액션(삭제)은 **빨강** 강조
  - **ESC / 배경 클릭**으로 닫기, **focus trap** 적용
- 삭제 확정 시: 대화방 삭제 API 호출 → `session_list_update`(op=`removed`)로 모든 탭 목록에서 제거
- **내가 보던 방이 다른 탭에서 삭제된 경우**: `session_list_update`(op=`removed`) 수신 시 "이 대화는 삭제되었습니다" 안내 후 목록으로 이동 ([messaging.md 대화방 목록 갱신](../common/messaging.md#대화방-목록-갱신-session_list_update))
- 대화 삭제해도 작업 히스토리는 독립 유지 (위 대화 관리 참조)

## AI 의도 분석

사용자 발화 → AI가 레시피 매칭:

- 참조 태그가 있으면 해당 레시피 우선 참조
- 단일 레시피 매칭 → 액션 피커로 실행 모드 선택
- 복합 작업 판단 (여러 레시피 필요) → 플랜 제안 (액션 피커). 상세: [plan.md](../recipe/plan.md)
- 유사 레시피 여러 개 → 후보 선택 액션 피커
- 매칭 안 됨 → "해당 레시피가 없습니다. 레시피를 생성해주시면 좋겠습니다" 안내

## 패널 컨텍스트 전달 (참조 태그)

```
┌─────────────────────────────────────────────────┐
│  📎 주문 생성 레시피 참조 중          [✕ 해제]   │
├─────────────────────────────────────────────────┤
│  메시지를 입력하세요...                           │
└─────────────────────────────────────────────────┘
```

- 사이드 패널에서 레시피를 열면 참조 태그 자동 표시
- 채팅 전송 시 해당 ID가 함께 전달됨 (AI 의도 매칭 보조)
- [✕] 또는 패널 닫기/다른 뷰 전환 시 자동 해제
