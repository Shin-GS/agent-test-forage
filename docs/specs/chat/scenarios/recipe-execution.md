# 시나리오: 레시피 실행

## 트리거

- 의도 분류에서 [바로 실행] 또는 [값 확인 후 실행] 선택 시
- 플랜에서 [바로 실행] 선택 시

## 전체 흐름

```
실행 시작
    │
    ▼
채팅: PROGRESS 메시지 생성 (message_new, status:running)
대화방 상태: 🔄 처리 중
입력: 차단 + [중지] 버튼 표시
    │
    ▼
스텝 순차 실행 (FE 브라우저에서 외부 API 직접 호출)
    │
    ├─ 스텝 완료 → 같은 PROGRESS 메시지 갱신 (message_update, ✅ + 결과 한 줄 누적)
    │              BE에 스텝 결과 저장 API 호출
    │
    ├─ 사용자 입력 필요 (직접 입력 모드 or AI가 판단 불가)
    │     → 대화방 상태: 🟡 입력 대기
    │     → 액션 피커: 해당 변수 form (prefill 포함)
    │     → 입력 완료 후 → 다음 스텝 이어서 실행
    │
    ├─ 스텝 조건 미충족 → ⏭️ 스킵
    │
    ├─ 인증 에러 (401) → 카드 UI: [로그인하러 가기] [로그인 완료]
    │
    ├─ 권한 에러 (403) → 카드 UI: [다른 계정으로 로그인] [레시피 중단]
    │
    ├─ 실패 (500, 타임아웃 등) → ❌ + 카드 UI: [다시 실행]
    │
    └─ 전체 완료
          → PROGRESS status 확정 (message_update, success/failed)
          → 채팅: RESULT 메시지 생성 (message_new, 결과 요약 + resultValues)
          → 카드 UI: 결과 제공형 카드 ([결과 보기]는 프로토타입 비활성/생략)
          → 히스토리 refresh
          → 대화방 상태: 유휴 (session_status: idle)
```

## UI 동작

### 진행 상태 블록 (채팅에 스크롤 메시지로 표시)

```
📋 입사지원 실행 중

✅ 1. 로그인 확인 — 성공
✅ 2. 이력서 확인 — "프론트엔드 개발자 이력서" 발견
⏭️ 3. 회원가입 (스킵)
🔄 4. 공고 선택 (입력 대기 중)
⬜ 5. 입사지원 제출
```

### 입력 차단 영역

```
┌─────────────────────────────────────────────┐
│  레시피 실행 중...                    [중지]  │
└─────────────────────────────────────────────┘
```

### 사용자 입력 필요 시 액션 피커

```
┌──────────────────────────────────────┐
│ 공고를 선택해주세요             [✕]   │
│                                      │
│ 🔍 [네이버 백엔_________]            │
│   네이버 백엔드 개발자 (3년차)        │
│   네이버 백엔드 시니어 (7년차)        │
│                                      │
│           [취소]  [선택 완료]         │
└──────────────────────────────────────┘
```

- prefill된 값은 출처 뱃지 표시 (🗣️🔗📌)
- [취소] → 전체 레시피 중단

### 완료 시

```
📋 입사지원 완료 ✅

AI: 입사지원이 완료되었습니다.
    - 지원번호: APP-2026-0831
    - 공고: 네이버 백엔드 개발자

┌─────────────────────────────────────────┐
│ 📄 입사지원 결과                         │
│ 2026-08-27 14:30                        │
│              [결과 보기] (프로토타입 비활성) │
└─────────────────────────────────────────┘
```

- 진행/완료는 PROGRESS 메시지(스텝 누적, `message_update`) + 완료 시 RESULT 메시지(`message_new`)로 흐른다. 상세: [execution.md 실행 완료](../../recipe/execution.md#실행-완료--결과-요약) · [messaging.md 실행 SSE 흐름](../../common/messaging.md#실행-sse-흐름-message_new--message_update)
- 결과 제공형 카드는 노출하되 `[결과 보기]`는 사이드 패널 미구현으로 프로토타입에서 비활성/생략한다.

## 플랜 실행 모드

플랜(레시피 여러 개)인 경우:

```
📋 플랜 실행 중

✅ 1. 이력서 작성 — 이력서 ID: RES-001
🔄 2. 포지션 탐색
   ├ ✅ 로그인
   ├ 🔄 포지션 목록 조회
   └ ⬜ 결과 추출
⬜ 3. 입사지원
```

- 현재 실행 중인 레시피만 스텝 펼침
- 완료된 레시피는 접힘 (결과 한 줄)
- 레시피 간 데이터 전달: 이전 레시피 결과 정의(④) → 다음 레시피 입력으로 자동 매핑
- 실패 시: 전체 중단 + "레시피 N에서 실패. 이전 레시피는 이미 완료됨" 안내

---

## 중지

- [중지] 클릭 → 현재 스텝까지 완료 후 중단
- 진행 상태: ⏹️ 표시 (PROGRESS status 확정)
- 종료 사유: `STOPPED` outcome으로 EXECUTION 계층에 기록 (사유 + 완료 스텝 수)
- 히스토리: 중단 기록으로 보존 (예: "중지됨 · 1/3 스텝 완료")
- 중단 지점부터 재개하는 [이어서 실행]은 **추후** (프로토타입은 처음부터 다시 실행만 제공). 상세: [execution.md 이어서 실행](../../recipe/execution.md#이어서-실행)

## 프롬프트

레시피 실행 자체에는 AI 호출 없음 (FE가 스텝 순서대로 API 호출).
AI가 관여하는 순간:
- "AI 생성" 값 소스 필드 → ai-generation.md 참조
- 실행 완료 후 결과 템플릿 미정의 시 → result-summary.md 참조
- prefill (대화 맥락에서 값 추출) → intent-classification에서 extractedValues로 이미 처리됨
