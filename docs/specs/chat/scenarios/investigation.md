# 정보 조회 루프 (investigate)

## 개요

사용자가 정책/기능에 대해 물어볼 때("이 회원가입 정책이 뭐야?"), AI가 답변에 필요한 정보를 스스로 조회하는 agentic loop.

- 단발성이 아님: AI가 "추가 정보가 필요한지" 판단하여 반복 조회
- 읽기 전용: 외부 데이터를 생성하지 않으므로 사용자 승인 불필요
- 조회 소스는 커넥터로 추상화 (프로토타입: `api_spec`, `jira`)

## 왜 필요한가

API 스펙만으로는 "왜 이렇게 동작하는지" 정책 맥락을 알 수 없다. Jira 티켓 등 추가 소스를 참조해야 테스트 시 "이 기능이 어떤 정책인지"를 정확히 답할 수 있다.

## 플로우

```
사용자: "회원가입 시 약관 동의 정책이 어떻게 돼?"
    │
    ▼
AI: investigate(source: api_spec, query: "회원가입")
    │  → 요청 스키마에 agreementYn 필드 발견
    ▼
AI 판단: "약관 필드는 있는데 정책 근거가 없다. Jira 확인 필요"
    │
    ▼
AI: investigate(source: jira, query: "회원가입 약관 동의")
    │  → PROJ-1234 "만 14세 미만 보호자 동의 필수" 발견
    ▼
AI 판단: "충분하다"
    │
    ▼
AI: chat(answer + references)
    │  → 답변 + [🎫 PROJ-1234] [📋 POST /api/v1/users] 버튼
    ▼
FE: 답변 메시지 + 참고 자료 카드 렌더링
```

## BE 처리 (루프)

```
1. 사용자 발화 → AI 호출
2. AI가 investigate 반환
3. BE: 해당 커넥터로 조회 → 결과를 messages에 추가
4. BE: 조회 진행 상태를 SSE로 FE에 전송 ("🔍 {source} 조회 중")
5. AI 재호출 (조회 결과 포함)
6. AI가 또 investigate 반환하면 → 3번으로 (루프)
   AI가 chat 반환하면 → 최종 답변 + 참고 자료 → 종료
7. 루프 제한: 최대 5회 / 타임아웃 120초 (ai-config.md)
```

## 진행 상태 표시 (SSE)

조회 과정을 progress 컴포넌트로 실시간 표시:

```
🔍 정보 조회 중

✅ API 스펙 확인 — 회원가입 스키마
🔄 Jira 조회 중 — "회원가입 약관"
```

- 각 조회 단계가 SSE 이벤트로 전송됨
- 완료 시 실제 답변 메시지로 교체

## 참고 자료 표시

조회한 소스의 원본 링크를 답변 하단에 버튼 리스트로 표시.
상세: [카드 UI - 참고 자료 카드](../card-ui.md)

```
AI: 회원가입 시 약관 동의는 필수이며, 만 14세 미만은 보호자 동의가 필요합니다.

참고한 자료:
[🎫 PROJ-1234 회원가입 정책]  [📋 POST /api/v1/users]
```

## 호출 주체

정보 조회는 **모두 ai-test-forge 서버(BE)가 호출**한다. 레시피 실행(FE 브라우저 직접 호출)과 다르다.

| 작업 | 호출 주체 | 인증 |
|------|----------|------|
| 레시피 API 실행 | FE 브라우저 | 외부 서버 쿠키 세션 |
| investigate → api_spec | BE | 내부 DB 조회 |
| investigate → jira | BE | 서버 시크릿 토큰 |

이유: AI 루프가 BE(OpenAI 호환 API 직접 호출, OpenRouter)에서 돌고, Jira 토큰은 서버 시크릿이라 FE에 노출할 수 없다.

## 커넥터별 조회 내용

| 커넥터 | 조회 결과 | 참고 링크 |
|--------|----------|----------|
| `api_spec` | 요청/응답 스키마, 어노테이션 힌트, description | 스펙 상세 (사이드 패널 or 내부 링크) |
| `jira` | 티켓 제목/본문/상태 | Jira 티켓 URL (새 탭) |

### Jira 커넥터 설정

| 항목 | 위치 |
|------|------|
| 조회 프로젝트 (`projectKey`) | 서비스별 (yml / 관리자) — [스펙 등록](../../spec/registration.md#jira-연결-정보-조회용) |
| Jira 인스턴스 baseUrl + API 토큰 | ai-test-forge 서버 환경변수 (시크릿) |

- 대화방 서비스에 연결된 `projectKey` 범위로 조회 (엉뚱한 프로젝트 방지)

## 루프 종료 조건

| 조건 | 동작 |
|------|------|
| AI가 chat 반환 | 최종 답변 + 참고 자료 → 정상 종료 |
| 최대 조회 5회 도달 | 수집된 정보로 답변 or "정보 부족" 안내 |
| 타임아웃 120초 | 중단 + "조회 시간이 초과되었습니다" 안내 |
| 조회 실패 (커넥터 에러) | 해당 소스 스킵, AI에게 실패 전달 → 다른 소스 시도 or 답변 |

## 제약 (프로토타입)

- 커넥터: `api_spec`, `jira`만 실제 구현
- `figma`는 추후 (key 확보 + 사용성 검증 후) — 커넥터 인터페이스는 확장 가능하게 설계
- Jira 인증(토큰)은 서버 환경변수로 관리, 조회는 BE가 수행. 사용자별 인증은 추후

## 보안

- 읽기 전용이므로 외부 데이터 변경 없음
- Jira 조회 결과에 민감 정보 포함 가능 → 로깅 시 마스킹 (참조: [error-handling.md](../../common/error-handling.md))
- 조회 대상은 등록된 서비스/연동된 소스로 제한 (임의 URL 조회 불가, SSRF 방지)
