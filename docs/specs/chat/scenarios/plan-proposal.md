# 시나리오: 플랜 제안

## 트리거

AI가 [Tool Use 호출](intent-classification.md)에서 `propose_plan` tool을 선택한 경우
(여러 레시피를 순서대로 실행하는 복합 작업).

## 전체 흐름

```
Tool Use에서 propose_plan 호출 (recipeIds: [1, 3, 5], rationale)
    │
    ▼
BE: recipeIds로 레시피 상세 조회 (이름, 설명, 기본값)
    │
    ▼
채팅: FE 고정 템플릿 (레시피 이름 순서로 구성) + rationale 근거
액션 피커: 플랜 제안 UI (인터랙티브 — 스킵/순서변경 가능)
    │
    ├─ 사용자 편집: 레시피 스킵(체크박스) / 순서변경(↑/↓ 이동) / 값 사전 편집([값 지정] 아코디언)
    │
    ├─ (백로그) 레시피 제거/추가
    │
    └─ [자동 실행] → 체크된 항목만 화면 순서대로 recipeIds + recipeInputs 구성 → recipe-execution (플랜 모드)
```

---

## AI 응답 (tool call)

```json
{
  "toolCalls": [
    {
      "function": {
        "name": "propose_plan",
        "arguments": {
          "recipeIds": [1, 3, 5],
          "rationale": "입사지원은 이력서·포지션이 선행돼야 해 3단계로 구성"
        }
      }
    }
  ]
}
```

- `propose_plan`은 **message를 생성하지 않는다.** 안내 문구는 FE가 `recipeIds`로 레시피 상세를 조회해 고정 템플릿으로 구성한다.
- `rationale`(1단계 필수)은 **제안 카드에 근거로 그대로 노출**한다. 사용자가 조합의 타당성을 판단하는 근거가 된다. tool 스펙: [intent-classification.md `propose_plan`](intent-classification.md#propose_plan).
- 플랜 모드는 항상 `AUTO`로 고정 (MODE 선택 없음).
- **`recipeIds`가 1개면 BE에서 `execute_recipe`로 폴백**한다(단일 실행). 필터링으로 1개만 남은 경우도 동일(로그만). 폴백 시 **`rationale`은 사용하지 않는다**(단일 실행 표시).
- **`extractedValues`는 1단계 플랜 제안에서 사용하지 않는다.** 발화 추출값을 여러 레시피 중 어디에 매칭할지(레시피별 분배) 규칙이 1단계 범위 밖이기 때문이다. 발화값은 실행 시점 각 레시피 pre-run에서 "같은 key면 시드"로만 재활용된다([plan.md 데이터 자동 채움](../../recipe/plan.md#데이터-자동-채움-우선순위-실행-중-액션-피커)). 따라서 제안 카드 값 미리보기에는 **레시피 기본값(📌)만 확정 표시**하고 나머지는 "실행 중 결정"으로 둔다(아래 값 미리보기).

---

## UI 동작

| 영역 | 동작 |
|------|------|
| 채팅 | FE 고정 템플릿 (레시피 이름 순서) + rationale 근거 문구 |
| 액션 피커 | 플랜 제안 카드 (인터랙티브 — 스킵/순서변경 가능, 아래 참조) |
| 사이드 패널 | 변화 없음 |
| 대화방 상태 | 🟡 입력 대기 |

### 액션 피커: 플랜 제안 (인터랙티브)

각 행은 `[↕ ↑/↓ 이동 버튼] [체크박스] [순서번호] [레시피명] [서비스 뱃지] [값 지정 토글]`와 값 미리보기로 구성된다. 사용자는 레시피를 **스킵**(체크박스), **순서변경**(↑/↓ 이동), **값 사전 편집**([값 지정] 아코디언)할 수 있다.

```
┌─────────────────────────────────────────────────────────┐
│ 📋 실행 계획                                       [✕]   │
│ 💡 입사지원은 이력서·포지션이 선행돼야 해 3단계로 구성      │
│ (전체 3단계 중 3단계 실행)                                │
│                                                         │
│ ↑↓  ☑  1.  이력서 작성   [사람인]            [값 지정 ▸]  │
│           경력: "3년" 📌  ·  이름: 실행 중 결정            │
│ ↑↓  ☑  2.  포지션 탐색   [사람인]            [값 지정 ▸]  │
│           직무: "백엔드" 📌  ·  지역: 실행 중 결정          │
│ ↑↓  ☑  3.  입사지원      [사람인]            [값 지정 ▸]  │
│           지원 메모: 실행 중 결정                          │
│                                                         │
│            [취소]  [자동 실행]                             │
└─────────────────────────────────────────────────────────┘
```

- 상단에 `rationale`(AI 근거)을 💡로 노출.
- 헤더 카운터 "(전체 N단계 중 M단계 실행)"은 스킵을 반영해 실시간 갱신한다.
- **순서번호는 체크된 항목만** 세어 1, 2, 3… 재매김한다.
- 값 미리보기(접힘 상태)는 기존 규칙(아래 [값 미리보기](#값-미리보기-결정-1--정직하게-축소))을 그대로 유지한다. [값 지정]은 기본 접힘이라 접혀 있으면 카드는 기존처럼 깔끔하다.
- 레시피 추가·제거는 제공하지 않는다([2단계 백로그](#2단계-백로그-여기서-미구현)).

### 편집 상태 카드 (스킵 반영)

일부 레시피를 스킵한 상태. 스킵된 행은 흐리게 + "(제외됨)" 표기하고 순서번호를 부여하지 않는다. 체크된 항목만 순서번호를 다시 매긴다.

```
┌─────────────────────────────────────────────────────────┐
│ 📋 실행 계획                                       [✕]   │
│ 💡 입사지원은 이력서·포지션이 선행돼야 해 3단계로 구성      │
│ (전체 3단계 중 2단계 실행)                                │
│                                                         │
│ ↑↓  ☑  1.  이력서 작성   [사람인]                         │
│           경력: "3년" 📌  ·  이름: 실행 중 결정            │
│ ↑↓  ☐      포지션 탐색  (제외됨)          ← 흐리게, 번호 없음 │
│ ↑↓  ☑  2.  입사지원      [사람인]                         │
│           지원 메모: 실행 중 결정                          │
│                                                         │
│            [취소]  [자동 실행]                             │
└─────────────────────────────────────────────────────────┘
```

편집 규칙(확정):

| 규칙 | 동작 |
|------|------|
| 순서변경 | ↑/↓ 이동 버튼으로 재배치(드래그 아님, 키보드 조작 가능). 이동 시 aria-live로 announce |
| 스킵 반영 | 스킵 행 흐리게 + "(제외됨)", 순서번호 미부여. 헤더 카운터 실시간 갱신 |
| 값 사전 편집 | 행의 [값 지정] 아코디언에서 그 레시피 입력 변수 전부 편집. 편집한 행에 "값 지정됨" 뱃지. 스킵 행은 아코디언 비활성 (아래 [값 사전 편집 아코디언](#값-사전-편집-아코디언-결정-3--4)) |
| 최소 1개 가드 | 전부 스킵이면 [자동 실행] 비활성 + "최소 1개 선택" 안내 |
| 1개만 남음 | 그대로 실행(BE가 SINGLE 수렴). 버튼 문구 "자동 실행" 유지 |
| 실행/취소 후 | 카드 편집 잠금 |

- 사용자의 스킵/순서변경/값 편집은 **카드 로컬 상태**로만 관리하고 **서버에 저장하지 않는다.** 카드 payload(원본 `recipeIds`/`recipes`/`variables`)는 그대로 두므로 **새로고침 시 원래 제안이 복원**된다.
- [자동 실행] 시 FE가 **체크된 항목만, 화면 순서대로** `recipeIds`를 구성하고, 같은 순서로 `recipeInputs`(사전 편집값)를 정렬해 `startPlan`(POST `/conversations/{id}/plan-executions {recipeIds, recipeInputs}`)에 전달한다. 스킵·순서변경은 BE 변경 없음, 값 사전 편집은 `recipeInputs` 확장 — 상세: [plan.md 제안 카드 편집](../../recipe/plan.md#제안-카드-편집-2단계--스킵--순서변경--값-사전-편집).

### 값 사전 편집 아코디언 (결정 3 · 4)

각 레시피 행의 [값 지정] 토글을 펼치면 그 레시피 변수 입력 폼이 나타난다. **기본은 접힘.** 폼은 카드 payload의 `variables`(변수 스키마: name/label/type/required/default/options)로 그리며, 기존 **액션 피커 필드 컴포넌트를 재사용**한다(별도 API 조회 없음).

```
┌─────────────────────────────────────────────────────────┐
│ ↑↓  ☑  1.  이력서 작성   [사람인]            [값 지정 ▾]  │
│      ┌───────────────────────────────────────────────┐  │
│      │ 경력   [ 5년          ]  (필수)                │  │
│      │ 이름   [ 홍길동        ]                        │  │
│      │ 분야   [ 백엔드 ▾      ]  (select)             │  │
│      └───────────────────────────────────────────────┘  │
│ ↑↓  ☑  2.  포지션 탐색   [사람인]  값 지정됨   [값 지정 ▸]│
│           직무: "백엔드" 📌  ·  지역: 실행 중 결정          │
└─────────────────────────────────────────────────────────┘
```

값 사전 편집 규칙(확정):

| 규칙 | 동작 |
|------|------|
| 노출 범위 | 그 레시피의 입력 변수 **전부** (기본값 있는 것도 편집 가능) |
| 편집 뱃지 | 값을 편집한 레시피 행에 "값 지정됨" 뱃지 표기 |
| 스킵 상호작용 | 스킵된 레시피는 아코디언 비활성 (실행 대상 아님) |
| 폼 렌더링 | 카드 payload `variables` 스키마로 액션 피커 필드 컴포넌트 재사용 |
| 접근성 | 토글은 `aria-expanded`로 상태 노출, 키보드 조작 가능 |
| 로컬 상태 | 편집값은 카드 로컬 상태로만 관리, 서버 미저장, 새로고침 시 복원 |

- 편집값은 [자동 실행] 시 `recipeInputs`로 구성되어 실행 시 해당 레시피 시드로 사용된다. 사전 편집으로 required가 다 채워지면 그 레시피는 **pre-run 액션 피커 없이 통과**한다(자동 실행이 안 멈춤). 우선순위: 이전 결과 > **사전 편집(✍️)** > 발화 > 기본값 > 직접 입력 ([plan.md 데이터 자동 채움](../../recipe/plan.md#데이터-자동-채움-우선순위-실행-중-액션-피커)).

### 값 미리보기 (결정 1 — 정직하게 축소)

값 미리보기는 **[값 지정] 아코디언이 접힌 상태의 한 줄 요약**이다(펼치면 위 [값 사전 편집 아코디언](#값-사전-편집-아코디언-결정-3--4)의 편집 폼으로 대체). 제안 시점에는 실행 결과가 없고, 발화 추출값의 레시피별 분배 규칙도 1단계 범위 밖이므로 **레시피에 정의된 기본값만 확정 표시**하고 나머지는 예측하지 않는다. 사용자가 아코디언에서 값을 지정하면 그 값은 요약에 반영하되, 미편집 변수의 예측 표시 원칙은 그대로 유지한다.

| 표시 대상 | 표시 방식 |
|-----------|-----------|
| 지금 확정된 값 (레시피 기본값) | 값 + 📌 기본값 |
| 나머지 전부 (발화 추출·이전 결과·직접 입력 등 실행 시점 결정) | **"실행 중 결정"** (예측 표시 안 함, 단일 표기로 통일) |

- **발화 추출값(🗣️)도 제안 카드 미리보기에는 표시하지 않는다.** 어느 레시피 변수에 속하는지 분배 규칙이 1단계에 없기 때문(발화값은 실행 시점 각 레시피 pre-run에서 같은 key면 시드로 재활용).
- **"이전 결과로 채워짐(🔗)" 예측 표시도 하지 않는다.** 실행 전에는 확정할 수 없기 때문이다.
- 🗣️ 발화 / 🔗 이전 결과 뱃지는 **실행 중 액션 피커에서만** 사용한다(그 시점엔 실제 값이 존재).

### 사용자 액션

| 동작 | UI | 결과 |
|------|------|------|
| 스킵 | 행 체크박스 해제 | 실행 대상에서 제외 (흐리게 + "(제외됨)", 카운터 갱신) |
| 순서변경 | 행의 ↑/↓ 이동 버튼 | 실행 순서 재배치 (aria-live announce) |
| 값 사전 편집 | 행의 [값 지정] 아코디언 펼침 → 변수 입력 | 편집값을 로컬 상태에 저장, 행에 "값 지정됨" 뱃지 |
| 자동 실행 | [자동 실행] 클릭 | 체크된 항목만 화면 순서대로 `recipeIds` + `recipeInputs`(사전 편집값) 구성 → 플랜 실행 진입 ([execution.md 플랜 실행](../../recipe/execution.md#플랜-실행)) |
| 취소 | [취소] 또는 [✕] | 취소 API 호출 → "취소되었습니다" → 채팅 input 복귀 (아무 실행 안 함) |

- **[취소]는 아직 아무것도 실행하지 않은 상태의 취소**다. 실행 중 [중단]과는 다르다([plan.md 사용자 중단](../../recipe/plan.md#사용자-중단-실행-중)).

## 2단계 백로그 (여기서 미구현)

레시피 스킵·순서변경·값 사전 편집은 **확정**되어 위 [편집 상태 카드](#편집-상태-카드-스킵-반영)·[값 사전 편집 아코디언](#값-사전-편집-아코디언-결정-3--4)에 반영했다. 아래는 여전히 미구현으로 남긴다.

| 항목 | 설명 |
|------|------|
| 레시피 제거/추가 | [🗑] / [+ 레시피 추가] 인라인 검색 |
| 복잡한 데이터 매핑 | 서로 다른 key 간 결과 매핑 (1단계는 같은 key 자동 전달만) |
| [이어서 실행] | PARTIAL 재개 — 실패/중단된 레시피부터 재개 |

## 프롬프트

플랜 제안 자체는 Tool Use 호출(`propose_plan`) 단계에서 이미 결정됨.
별도 AI 호출 없음 (BE가 `recipeIds` 배열로 레시피 상세를 조회하여 FE에 전달, `rationale`은 tool 인자로 함께 전달).

- 제안 카드 payload에는 값 미리보기용 `inputPreview`뿐 아니라 **각 레시피의 `variables`(전체 변수 정의: name/label/type/required/default/options)**를 함께 실어 FE가 [값 지정] 아코디언 편집 폼을 별도 조회 없이 그린다([plan.md 변수 스키마 전달](../../recipe/plan.md#결정-3-변수-스키마를-카드-payload에-전달)).
