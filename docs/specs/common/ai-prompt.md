# AI 프롬프트 설계

## 모델 구성

| 역할 | 모델 | 용도 |
|------|------|------|
| reasoning | GPT-4o (또는 동급) | 의도 분석, 플랜 구성 |
| fast | GPT-4o-mini (또는 동급) | AI 생성(필드 값), 이력 요약, 결과 요약 |

모델 교체는 설정만 변경하면 됨. 구조는 모델에 종속적이지 않음.

---

## 토큰 절약 전략

### 단계적 호출

한번에 모든 정보를 보내지 않고, 가벼운 판단 → 필요한 것만 추가 로드:

```
1단계: [fast] 의도 분류 + 서비스/레시피 매칭
  - 입력: 발화 + 해당 서비스의 레시피 이름+설명 목록
  - 결과: intent + recipeId or plan

2단계: [reasoning] 필요 시 상세 (플랜 구성, 값 추출)
  - 입력: 매칭된 레시피 상세 + 대화 이력
  - 결과: 플랜 순서, extractedValues
```

### 프롬프트 캐싱

- 시스템 프롬프트 + 레시피 목록을 동일한 prefix로 구성
- OpenAI는 동일 prefix 반복 호출 시 자동 캐싱 (비용 50% 절감)
- 변하는 부분(이력 + 발화)은 suffix로

### 이력 압축

- 최근 3~5건 원문 + 그 이전은 요약 1문단
- 요약은 매 5턴마다 fast 모델로 생성해서 BE에 저장
- 레시피 실행 결과: 스텝별 한 줄 요약 + extract된 key-value만 (원시 JSON 제외)

### 레시피 목록 필터링 (AI 호출 전 BE에서 처리)

- 대화방 서비스 설정됨 → 해당 서비스 레시피만 전달 (500개 → 15~20개)
- 서비스 미지정 → 서비스 목록(30개 이름만) 전달하여 먼저 서비스 확정
- AI에게 500개 전체를 보내는 일은 없음

### Function Calling

- AI 응답을 JSON으로 강제 (불필요한 텍스트 출력 방지)
- 출력 토큰 절약 + 파싱 에러 방지

## AI 호출 구조 (전체 플로우)

### 서비스 지정된 상태

```
사용자 발화
    │
    ▼
BE: 컨텍스트 조립
  - 해당 서비스의 레시피 목록 (이름+설명+태그, 15~20개)
  - 최근 이력 (3~5건 원문 + 요약)
  - 참조 태그 (있으면)
  - 시스템 프롬프트
    │
    ▼
[fast] 의도 분류 (1회 호출)
    │
    ├─ recipe_match → 액션 피커 (실행 모드 선택)
    ├─ plan → 액션 피커 (플랜 제안)
    ├─ no_match → "레시피 없음" 안내
    └─ clarify → "좀 더 구체적으로" 요청
```

### 서비스 미지정 상태

```
사용자 발화
    │
    ▼
[fast] 서비스 유추 (서비스 목록 30개 이름만 전달)
    │
    ├─ 유추 가능 → 액션 피커: "XX 서비스 맞나요?" [서비스A] [서비스B]
    │               → 선택 시 대화방 서비스 설정 → 위 플로우 진입
    │
    └─ 유추 불가 → 액션 피커: "어느 서비스에서 진행할까요?" [서비스 목록]
```

## AI 응답 형식 (Function Calling)

### 의도 분류 응답

```json
{
  "intent": "recipe_match | plan | no_match | clarify | service_select",
  "recipeId": 123,
  "plan": [123, 456, 789],
  "suggestedServices": ["사람인", "잡코리아"],
  "extractedValues": {
    "positionId": "1"
  },
  "message": "사용자에게 보여줄 메시지"
}
```

### AI 생성 (필드 값) 응답

```json
{
  "value": "생성된 값"
}
```

## 역할별 프롬프트 구조

### 의도 분류 시스템 프롬프트

```
당신은 API 워크플로우 실행 도우미입니다.

## 원칙
- 확실하지 않으면 추측하지 말고 clarify로 응답
- 레시피 목록에 없는 작업은 no_match로 응답
- 여러 레시피가 순서대로 필요하면 plan으로 응답
- 응답은 반드시 지정된 JSON 형식으로

## 사용 가능한 레시피
{레시피 목록 JSON}

## 현재 대화방 서비스
{서비스명}

## 최근 대화 이력
{이력 요약 + 최근 원문}
```

### AI 생성 (필드 값) 시스템 프롬프트

```
API 요청의 특정 필드에 적절한 테스트 값을 생성해주세요.

## 정보
- API: {method} {path}
- 필드: {필드명} ({타입})
- API 설명: {description}
- AI 힌트: {hint}
- 현재 컨텍스트: {이전 스텝 결과}

값만 반환하세요. 설명 불필요.
```

### 결과 요약 (템플릿 미정의 시) 시스템 프롬프트

```
레시피 실행 결과를 사용자에게 간결하게 요약해주세요.

## 레시피: {이름}
## 실행 결과:
{스텝별 결과 요약}

2~3줄로 핵심 결과만 요약하세요.
```

---

## 프로토타입 제약

- 플랜은 1개 서비스의 레시피만 대상 (서비스 간 플랜은 추후)
- 프롬프트는 코드에 하드코딩 (추후 DB/설정으로 이동 가능)
- 이력 요약은 단순 잘라내기로 시작, 추후 AI 요약 도입

## 추후 확장

| 항목 | 설명 |
|------|------|
| 서비스 간 플랜 | 여러 서비스의 레시피를 조합하는 플랜 |
| 임베딩 기반 레시피 검색 | 키워드 매칭 대신 벡터 유사도 검색으로 더 정확한 매칭 |
| 프롬프트 관리 UI | 관리자가 프롬프트를 웹에서 수정 가능 |
| 대화 이력 AI 요약 | 매 N턴마다 AI가 이력을 요약하여 저장 |
