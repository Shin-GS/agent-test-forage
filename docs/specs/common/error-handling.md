# 에러 처리 정책

## 레시피 실행 중 에러

스텝 실행 중 에러(500, 타임아웃 등) 발생 시:

- 진행 상태에서 해당 스텝을 ❌ 표시
- AI가 "스텝 N에서 실패했습니다" 메시지 출력
- 카드 UI로 [다시 실행] 버튼 표시 (실패한 스텝부터 재개)

## 인증/권한 에러 (401/403)

레시피 실행 중 인증/권한 에러 감지 시, 상태코드에 따라 다르게 처리:

### 401 — 미인증 (로그인 필요)

1. 카드 UI 표시: [로그인하러 가기] + [로그인 완료]
2. [로그인하러 가기] → 새 탭으로 해당 서브도메인의 loginPageUrl
3. [로그인 완료] 클릭 → 중단된 스텝부터 재개
4. 여전히 401 → "로그인이 처리되지 않은 것 같습니다. 다시 로그인 부탁드립니다." + 같은 카드 재노출

### 403 — 권한 부족 (로그인은 됐으나 접근 권한 없음)

401과 **동일한 "인증 대기" 상태 모델**로 다룬다(스텝을 실패로 확정하지 않고 대기시킨 뒤, 권한 있는 계정으로 전환하면 그 스텝부터 재개). 401과의 차이는 **문구와 액션 선택지**뿐이다.

1. 인증 대기 카드 표시(스텝은 실패 확정하지 않고 대기 — 재개 대상 유지). 상태 문구: "권한이 없습니다".
2. 카드 UI: [다른 계정으로 로그인] + [레시피 중단]
3. [다른 계정으로 로그인] → 새 탭으로 loginPageUrl (권한 있는 계정으로 전환)
4. [레시피 중단] → 실행 중지(`POST /conversations/{id}/stop`), 인증 대기 해제
5. 권한 있는 계정으로 로그인 완료 후 → [로그인 완료] 클릭 시 해당 스텝부터 재개
6. 여전히 403 → 같은 카드 재노출(권한 없는 계정 그대로 등)

> **설계 근거**: 인증(401/403)을 단일 인증 대기 상태(`authPause`)로 통일한다. 스텝을 실패로 확정하는 별도 경로를 두지 않아 상태 관리가 일관되고, 다중 서비스 인증 확장 시에도 같은 모델을 재사용한다. 403은 이 모델 위에서 문구·액션([레시피 중단] 제공)만 분기한다.
