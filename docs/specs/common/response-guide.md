# AI 응답 가이드

## 핵심 원칙

### 할루시네이션 금지

- AI가 확신할 수 없는 값을 추측해서 채우지 않는다
- 모르면 "모른다"고 명시하고 사용자에게 물어본다
- 잘못된 데이터로 API를 호출하면 되돌리기 어려우므로, 확인 없이 실행하지 않는다

### 사용자에게 물어봐야 하는 경우

| 상황 | AI 동작 |
|------|---------|
| 대화 이력에서 참조할 수 있는 값이 없음 | "어떤 XX를 사용할까요?" 액션 피커로 요청 |
| 후보가 여러 개여서 하나로 특정 불가 | 후보 목록 제시 후 선택 요청 |
| 사용자 발화가 모호함 | 명확히 재확인 |

### 확인 없이 진행해도 되는 경우

| 상황 | AI 동작 |
|------|---------|
| 대화 이력에 명확한 값이 있음 (1건) | "XX로 진행할까요?" 확인 후 실행 |
| 사용자가 발화에서 명시적으로 값을 지정함 | 해당 값으로 바로 세팅 |
| 레시피 변수에 기본값이 있고 자동 실행 모드 | 기본값 사용 |

## 대화 이력 전달

AI에게 메시지 전송 시 **설정된 "대화 이력 전달 수"**(기본 15건, [설정](../pages/settings.md)에서 조정)만큼의 최근 대화를 함께 전달한다.
전달 시 최근 일부는 원문, 그 이전은 요약으로 압축한다 (압축 전략: [ai-config.md](ai-config.md#이력-압축)).

### 포함 대상

| 메시지 타입 | AI에게 전달하는 내용 |
|------------|-------------------|
| text (사용자/AI) | 원문 그대로 |
| card (실행 완료 등) | 카드 메타 정보 (레시피명, executionId, 결과 상태) |
| progress (실행 진행) | 스텝별 한 줄 요약 + extract된 key-value만 |
| action_picker_response | 사용자가 입력한 values |

### 제외 대상 (토큰 절약)

- 원시 API 응답 JSON 전체
- 시스템 메시지 (heartbeat 등)
- progress의 반복 업데이트 (최종 상태만)

### 레시피 간 컨텍스트 전달

대화 이력에 이전 레시피 실행 결과가 포함되어 있으므로, AI가 자연스럽게 이전 결과를 참조 가능.

```
사용자: "신규 공고 만들어줘"
AI: [공고 생성 실행 → 완료] 공고번호: JP-123

사용자: "방금 만든 공고로 입사지원해줘"
AI: (이력에서 JP-123 인식) 공고 "백엔드 개발자" (JP-123)로 진행할까요?
```

이력에 없으면 추측하지 않고 물어봄:
```
사용자: "방금 만든 공고로 입사지원해줘"
AI: (이력에 공고 생성 없음) 어떤 공고로 입사지원할까요?
    이 대화에서 생성된 공고를 찾지 못했어요.
    (액션 피커: search-select)
```

## 표시명(label) 폴백 체인

비개발자가 결과를 이해하도록, 스텝·결과 값을 사람말로 표기한다. 표시명은 선택 입력이며, 없으면 아래 순서로 폴백해 **어떤 경우에도 표기가 깨지지 않는다**. (정의: [structure.md 표시명 폴백 체인](../recipe/structure.md#표시명label-폴백-체인))

| 대상 | 폴백 우선순위 |
|------|--------------|
| 스텝 표시명 | (1) 레시피 스텝에 등록한 표시명 → (2) 엔드포인트 `summary`(스펙 원천, 한글 가능) → (3) `method + path` |
| 결과키 표시명 | (1) 결과 정의(④)에 등록한 `label` → (2) 없으면 원본 key 그대로(`orderId` 등) |

- 채팅 요약은 사람말(표시명 기반)로, 상세·히스토리는 기술 원문(key/method+path) 노출을 허용한다([이원화](messaging.md#content-vs-payloadjson-필드-이원화) 유지).
- 중첩/배열 key(`items[0].price`)는 label 없으면 key 경로 그대로 표기하고, 값이 없거나 null이면 "값 없음"으로 표시한다.
- AI가 결과를 요약할 때도 이 폴백 체인으로 결정된 표시명을 사용한다(원본 key를 사람말로 임의 창작하지 않는다 — 할루시네이션 금지).

## 톤 & 형식

- 간결하고 명확하게
- 불필요한 인사/장식 최소화
- 실행 관련 안내는 한 두 줄로
- 에러 안내 시 원인 + 다음 행동을 같이 제시
