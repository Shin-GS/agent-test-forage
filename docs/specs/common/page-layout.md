# 별도 페이지 공통 원칙 (상단 바 · 목록 상태)

채팅 레이아웃을 벗어난 **별도 전체 화면 페이지**(레시피 관리/편집, 히스토리, 설정, 스펙 관리/상세, 사용자 관리)의 공통 규칙을 정의한다. 두 가지를 다룬다: (1) 상단 영역 구성, (2) 목록 페이지의 검색/필터 상태 관리. 페이지마다 제각각이던 것을 통일하고, 앞으로 추가되는 페이지도 같은 규칙을 따르게 한다.

## 핵심 원칙

> **제목만 있는 상단 헤더는 두지 않는다.** 좌측 사이드바가 현재 위치를 하이라이트하므로 페이지 제목을 상단에 다시 크게 표기하는 것은 정보 중복이다. 상단 바는 **기능(뒤로가기 · 저장 · 필터 · 액션)을 담을 때만** 존재한다.

이 원칙의 목적:
- **일관성**: 페이지마다 헤더 유무·높이가 달라 생기는 시각적 흔들림 제거.
- **공간 효율**: 리스트/폼 중심 화면에서 제목만 차지하던 상단 영역을 콘텐츠에 돌려준다.
- **확장성**: 새 페이지도 아래 판단 기준만 따르면 자동으로 통일된 상단을 갖는다.

## 판단 기준

페이지 상단이 담아야 할 요소에 따라 세 유형으로 나눈다.

| 유형 | 조건 | 상단 처리 | 컴포넌트 |
|------|------|-----------|----------|
| **목록형** | 검색·필터·정렬 또는 우측 액션(만들기/추가 등)이 있음 | 제목 헤더 없이 **툴바**로 시작. 우측 끝에 주요 액션 | `PageToolbar` |
| **상세/편집형** | 뒤로가기(← 목록으로)나 저장 등 컨텍스트 액션이 필요함 | 제목 헤더 대신 **액션 바**(뒤로가기 + 제목 + 우측 액션) | `PageActionBar` |
| **콘텐츠형** | 상단에 담을 기능이 없음(단순 조회 폼 등) | 상단 바 없음. 콘텐츠가 바로 시작 | (바 없음) |

- 세 유형 모두 페이지 제목은 **화면에 크게 노출하지 않되**, 접근성·브라우저 탭을 위해 **숨김 제목(`sr-only` `<h1>`) + `document.title`** 로 남긴다(아래 [접근성](#접근성) 참조).
- 상단 바를 직접 마크업하지 않고 공통 컴포넌트(`PageShell` + `PageToolbar`/`PageActionBar`)를 사용한다. 컴포넌트 규격은 디자인 시스템([system.html](../../design/shared/system.html)) 참조.

## 페이지별 적용

| 페이지 | 유형 | 상단 구성 |
|--------|------|-----------|
| 레시피 관리(`/recipes`) | 목록형 | 툴바(검색/서비스·범위·태그 필터/정렬) + 우측 [+ 레시피 만들기] |
| 레시피 편집(`/recipes/new`, `/{id}/edit`) | 상세/편집형 | [← 목록으로] + 레시피명 + [버전 기록] [저장] |
| 히스토리(`/history`) | 목록형 | 툴바(검색/서비스·상태 필터/기간) |
| 설정(`/settings`) | 콘텐츠형 | 상단 바 없음. 설정 섹션 카드가 바로 시작 |
| 스펙 관리(`/admin/specs`) | 목록형 | 카운트("총 N개") + 테이블. (검색/필터 없으면 툴바 없이 카운트 줄로 시작) |
| 스펙 상세(`/admin/specs/:id`) | 상세/편집형 | [← 목록으로] + 스펙명 + 상태 배지 + [비활성화]/[활성화] [삭제] |
| 사용자 관리(`/admin/users`) | 목록형 | 툴바(아이디 검색/카운트) + 우측 [+ 사용자 추가] |

- **관리자 화면의 "관리자 전용" 배지는 두지 않는다.** 관리자 전용 페이지는 사이드바 "관리" 섹션의 nav로 진입 자체가 관리자에게만 노출되므로, 화면 안에 별도 배지로 다시 표기하지 않는다(중복 제거).
- **스펙 상세의 뒤로가기·제목·액션은 페이지 최상단 액션 바에 둔다.** 콘텐츠 카드 안쪽에 파묻지 않는다(레시피 편집과 동일한 상단 위치·구조로 통일).

## 접근성

제목을 화면에서 크게 노출하지 않으므로, 다음을 보장한다.

- **숨김 제목**: 각 페이지에 시각적으로 숨긴 `<h1>`(`sr-only`)을 두어 스크린리더·접근성 트리에 페이지 제목이 남게 한다.
- **문서 타이틀**: 페이지 진입 시 `document.title`을 페이지별로 설정한다. 브라우저 탭·히스토리에서 위치를 식별할 수 있게 한다.
- 상단 바(툴바/액션 바)는 스크롤 시에도 접근 가능하도록 **sticky** 로 둔다.

### 제목 문구 컨벤션

`PageShell`이 `title`을 받아 아래 규칙으로 `sr-only <h1>`과 `document.title`을 만든다. 페이지마다 제멋대로 짓지 않고 통일한다.

| 대상 | 형식 | 예시 |
|------|------|------|
| `sr-only <h1>` (목록/콘텐츠형) | 페이지명 | `레시피 관리`, `실행 히스토리`, `설정`, `스펙 관리`, `사용자 관리` |
| `sr-only <h1>` (상세/편집형) | `페이지명 — {대상명}` | `스펙 상세 — demo-shop`, `레시피 편집 — 회원가입` |
| `document.title` | `{페이지명} · 테스트메이트` | `레시피 관리 · 테스트메이트`, `스펙 상세 · 테스트메이트` |

- 관리자 페이지라도 제목에 "관리자 ·" 접두를 붙이지 않는다(사이드바 "관리" 섹션 nav로 맥락이 자명).
- 상세형은 `sr-only`에 대상명을 포함해 접근성 트리에서 어떤 항목의 상세인지 알 수 있게 한다. `document.title`은 대상명 없이 페이지명 기준으로 간결히 둔다.

## 반응형

- 툴바는 좁은 화면에서 요소가 한 줄에 다 들어가지 않으면 **`flex-wrap`으로 다음 줄로 흐른다**(우측 액션 버튼 포함).
- 상단 바의 높이·좌우 패딩은 공통 토큰을 사용해 목록형·상세형이 동일한 시각 리듬을 갖게 한다(하드코딩 금지, [tokens.css](../../design/shared/tokens.css) 변수 사용).

## 목록 상태와 URL (목록형 페이지 공통)

목록형 페이지의 **검색·필터·정렬 상태는 컴포넌트 로컬 상태(`useState`)가 아니라 URL 쿼리스트링을 단일 진실 소스(source of truth)로** 관리한다. 화면은 URL에서 상태를 파생시킨다.

### 왜 URL인가

- **새로고침 견딤**: F5 해도 필터가 유지된다.
- **공유·북마크**: 필터가 걸린 URL을 그대로 공유하면 상대도 같은 화면을 본다(딥링크).
- **뒤로/앞으로**: 브라우저 히스토리와 자연스럽게 맞물린다.
- **일관성**: 모든 목록 페이지가 같은 방식이라 사용자가 예측 가능하고, 새 페이지도 빠뜨리지 않는다.

### 히스토리 반영 규칙 (필터=replace, 이동=push)

| 액션 | 히스토리 | 이유 |
|------|---------|------|
| 검색어 / 필터 / 정렬 변경 | **replace** | 목록 안에서의 미세 조정. 매 변경을 히스토리에 쌓으면 뒤로가기가 "필터 되돌리기"로 변질되어, 목록을 벗어나려면 여러 번 눌러야 하는 문제가 생긴다. |
| 목록 → 상세 진입 | **push** | 진짜 페이지 이동. 뒤로가기로 목록에 복귀할 수 있어야 한다. |
| 상세 → 목록 복귀 | (직전 목록 URL로 이동) | 아래 [상세 → 목록 복귀](#상세--목록-복귀-필터-유지) 참조. |

- 검색어는 타이핑마다 히스토리를 오염시키지 않도록 **디바운스(스로틀) 후 replace 커밋**한다(글자 단위로 뒤로가기가 쌓이는 것 방지).
- 필터 하나를 잘못 눌렀을 때는 뒤로가기가 아니라 **필터 초기화 버튼 / 개별 칩 제거(✕)**로 되돌린다(뒤로가기는 페이지 이동 용도로 지킨다).

### 구현 표준

- URL ↔ 상태 동기화는 **[nuqs](https://nuqs.47ng.com)** (타입 안전 URL 상태 라이브러리)를 사용한다. `useQueryStates`로 파라미터를 선언적으로 정의한다.
- 손으로 `URLSearchParams`를 파싱/조립하거나 `useState`로 필터를 관리하지 않는다(타입 미검증·직렬화 버그·중복 로직 방지).
- **enum 값(정렬 기준, 상태 등)은 허용값 화이트리스트로 파싱**하여 조작된 URL 값을 기본값으로 안전하게 흡수한다(`parseAsStringEnum`).
- 기본값은 URL에 기록하지 않는다(`clearOnDefault` — URL을 깔끔하게).
- 서버 조회 파라미터(React Query `queryKey` 등)는 URL에서 파생한 값을 사용한다.

### 상세 → 목록 복귀 (필터 유지)

목록에서 상세(레시피 편집, 스펙 상세 등)로 진입한 뒤 상단 액션 바의 **[← 목록으로]**를 누르면, **필터가 걸린 직전 목록으로 복귀**해야 한다.

- 목록 → 상세 진입 시 **현재 목록 URL(쿼리 포함)을 함께 전달**한다(라우터 navigation state).
- 상세의 뒤로가기는 전달받은 목록 URL이 있으면 그리로, **없으면(URL로 상세에 직접 진입한 경우) 기본 목록 경로로 폴백**한다.
- 이 로직은 공통 헬퍼로 표준화해 페이지마다 배선이 누락되지 않게 한다.

### 페이지별 목록 상태

| 페이지 | URL 파라미터 |
|--------|-------------|
| 레시피 관리 | `q`(검색), `spec`/`visibility`/`tag`(다중), `sort`/`dir`(정렬) |
| 히스토리 | `q`(검색), `spec`/`status`(다중), `from`/`to`(기간) |
| 사용자 관리 | `q`(아이디 검색) |

- **사이드 패널의 레시피 목록**은 예외다. 채팅 보조 탐색용 로컬 상태로, 딥링크/공유 니즈가 없어 URL에 싣지 않는다(채팅 URL 오염 방지). 별도 전체 화면 목록 페이지에만 위 규칙을 적용한다.
- 스펙 관리는 현재 검색/필터 UI가 없어 해당 없음(추가 시 위 규칙을 따른다).

## 새 페이지 추가 시

새 별도 페이지를 만들 때는:
1. [상단 바 판단 기준](#판단-기준)으로 유형을 정하고 `PageShell`로 감싼 뒤 필요한 슬롯(`toolbar`/`actionBar`)만 채운다. **제목 전용 헤더를 직접 마크업하지 않는다.**
2. 목록형이면 검색/필터/정렬을 **URL(nuqs)로 관리**한다([목록 상태와 URL](#목록-상태와-url-목록형-페이지-공통)). `useState`로 필터를 들지 않는다.
3. 상세 페이지가 있으면 목록→상세 진입 시 목록 URL을 전달하고, 상세의 뒤로가기가 직전 목록으로 복귀하게 한다.
