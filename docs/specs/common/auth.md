# 로그인, 권한/역할

## 로그인

아이디 + 비밀번호 방식. 서버가 bcrypt 해시로 검증한다([APP_USER](../../db/user.md#app_user)).

## 인증 방식

프로토타입 단계의 확정 인증 방식이다. OIDC/LDAP/소셜 로그인, JWT/Bearer/refresh 토큰은 **쓰지 않는다.**

### 인증 유지 (세션 쿠키)

- **서버 세션 + httpOnly 세션 쿠키** 방식으로 인증을 유지한다.
- 쿠키명: **`TESTFORGE_SESSION`**. 속성: `HttpOnly`, `SameSite=Lax`, 프로덕션에서는 `Secure`.
- 세션 만료(TTL): **idle timeout 30분** (마지막 요청 기준). 만료 시 서버가 **401**로 응답 → 재로그인.
- 세션 저장소는 **인메모리**(프로토타입, Redis 없음). 서버 재기동 시 세션이 사라지므로 재로그인이 필요하다.
- 쿠키 특성상 **여러 탭이 세션을 공유**하고, **새로고침 시에도 로그인 상태가 유지**된다.

### 인증 엔드포인트

| 메서드 | 경로 | 설명 |
|--------|------|------|
| POST | `/api/v1/auth/login` | 아이디+비밀번호 로그인. 성공 시 세션 생성 + 세션 쿠키 발급 |
| POST | `/api/v1/auth/logout` | 세션 무효화 + 세션 쿠키 삭제 |
| GET | `/api/v1/auth/me` | 현재 로그인 사용자 조회 (`id` / `username` / `name` / `role`) |

- 로그인 실패 메시지: **"아이디 또는 비밀번호가 올바르지 않습니다"** (아이디/비번 구분 노출 안 함).
- 로그아웃은 서버 세션을 무효화하고 세션 쿠키를 삭제한다.

### 역할 가드

- **모든 API는 인증 필수**다. 비로그인 요청은 **401**로 응답한다.
- **관리자 전용 API는 ADMIN 역할을 추가로 체크**한다(권한 미달 시 403).
- 관리자 전용 API는 **`/api/v1/admin/**` prefix**로 둔다. 이 경로는 ADMIN 역할 필수(미달 시 403). 사용자 관리·스펙 관리 등 관리자 API는 이 prefix 아래에 배치한다.
- `userId` / `role`은 **요청 파라미터가 아니라 세션에서 도출**한다. 클라이언트가 보낸 사용자 식별자를 신뢰하지 않는다.

### 세션 상태/역할 재확인 (비활성화·역할 변경 반영)

인증 필터는 **매 요청 시 세션의 사용자에 대해 `STATUS`/`ROLE`을 재확인**한다. 계정 비활성화·역할 변경은 **다음 요청부터 반영**된다.

- `STATUS = INACTIVE`이면 다음 요청에서 **401**로 거부하고 해당 세션을 폐기한다 → 재로그인 불가(비활성 계정).
- 역할 변경(ADMIN ↔ USER)은 다음 요청부터 **새 역할로 평가**된다(관리자 API 접근 권한 즉시 조정).
- **즉시 강제 로그아웃(세션 저장소 전체 순회)은 하지 않는다**(프로토타입). "이미 발급된 세션을 매 요청마다 재검증"하는 방식으로 반영 지연을 최소화한다.

### SSE 인증

- SSE 연결은 **세션 쿠키로 자동 인증**한다(EventSource `withCredentials: true`).
- 쿼리 토큰/유저ID를 쓰지 않으며, `userId`는 세션에서 도출한다. (상세: [messaging.md 인증](messaging.md#인증))

### 로컬 개발 (same-origin 프록시)

- 로컬에서는 FE(Vite)가 `/api`를 BE로 프록시해 **same-origin**으로 쿠키를 사용한다.
- 크로스 오리진/HTTPS 구성을 회피해 세션 쿠키가 개발 환경에서도 자연스럽게 동작한다.

### CSRF 방침

- SPA + `SameSite=Lax` + 프록시 same-origin 조합으로 방어한다.
- **프로토타입 단계에서는 CSRF 토큰을 도입하지 않는다.**
- rate limiting / 로그인 실패 잠금은 **백로그**(추후).

## 계정 생성 정책

- **셀프 회원가입 없음.** 사용자가 직접 가입하는 경로는 제공하지 않는다.
- 계정 생성은 **관리자가 관리자 페이지에서 직접 수행**한다. 입력값: 아이디 + 비밀번호 + 역할(일반 사용자/관리자). 상세는 [관리자 페이지](../pages/admin.md) 참조.
- **최초 관리자 계정**은 **서버 기동 시 seed로 자동 생성**한다. ADMIN 역할 계정이 하나도 없으면 `.env`의 초기 관리자 아이디/비밀번호로 생성하고, 이미 있으면 스킵한다. (수동 MySQL INSERT도 보조 수단으로 가능) 방법은 [사용자 도메인 DB 설계](../../db/user.md#최초-관리자-계정-생성) 참조.

## 권한/역할

| 역할 | 권한 |
|------|------|
| **일반 사용자** | 채팅, 레시피 실행, 개인 레시피 작성, 히스토리 조회 |
| **관리자** | 일반 사용자 기능 + 공통 레시피 작성 + 사용자 관리 + 스펙 관리 |
