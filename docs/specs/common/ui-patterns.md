# UI 상호작용 패턴 (모달 vs 페이지 vs 드로어)

"어떤 화면을 모달로 띄우고, 어떤 것을 별도 페이지로 두고, 어떤 것을 드로어로 얹을지"의 판단 기준을 통일한다. 새 화면을 추가할 때 이 문서의 기준을 먼저 적용한다. 상단 바 구성·목록 상태 규칙은 [page-layout.md](./page-layout.md)를 함께 참조한다.

## 핵심 원칙

> **그릇(모달/페이지/드로어)은 콘텐츠의 성격으로 정한다.** "독립적으로 보는 결과물"이냐, "작업 맥락 안에서 잠깐 참조하는 것"이냐, "짧게 끝나는 결정·입력"이냐로 갈린다. 무겁다고 무조건 페이지가 아니고, 짧다고 무조건 모달이 아니다.

## 판단 기준

| 콘텐츠 성격 | 그릇 | 이유 | 예시 |
|-------------|------|------|------|
| **독립적으로 보는 결과물** (그 자체가 목적지, 링크 공유·북마크 가치, 오래 머무름, 스크롤 김) | **별도 페이지** | 딥링크·새로고침 유지·뒤로가기·넓은 화면 활용이 필요 | 히스토리 실행 결과 상세(`/history/:executionId`), 레시피 편집, 스펙 상세 |
| **작업/편집 맥락 안에서 잠깐 비교·참조** (뒤 화면이 살아있어야 흐름 유지, 딥링크 가치 낮음) | **드로어 / 모달** | 맥락을 떠나면 오히려 흐름이 끊김 | 레시피 버전 기록(드로어), 레시피 버전 미리보기(모달) |
| **짧게 끝나는 결정 (yes/no)** | **모달** | 즉시 끝나고, 뒤 화면 유지가 중요 | 삭제/중지/복원 확인(`ConfirmModal`), 실행 중지 확인 |
| **짧은 입력 (폼)** | **모달** | 잠깐 뜨는 폼, 딥링크 불필요 | 사용자 생성, 비밀번호 변경 |

### 페이지가 맞는 신호

- 콘텐츠를 링크로 공유하거나 북마크할 가치가 있다.
- 새로고침해도 그 화면이 유지돼야 한다.
- 모바일에서 전체 화면을 쓰는 게 자연스럽다.
- 콘텐츠가 길어 스크롤이 많고, 오래 들여다본다.

### 모달/드로어가 맞는 신호

- 상호작용이 짧게 끝난다(확인·간단 입력).
- 뒤에 있는 화면이 사라지면 안 된다(맥락 유지).
- 한 화면에 들어오고 스크롤이 거의 없다.
- 딥링크·공유가 필요 없다.

## 현재 프로젝트 적용 현황

| 사용처 | 그릇 | 근거 |
|--------|------|------|
| 히스토리 실행 결과 상세 | **페이지**(`/history/:executionId`) | 독립 결과물 + 공유/딥링크 가치. [pages/history-full.md](../pages/history-full.md#실행-결과-상세-별도-페이지) |
| 레시피 편집 | 페이지(`/recipes/:id/edit`) | 독립 편집 화면 |
| 스펙 상세 | 페이지(`/admin/specs/:id`) | 독립 조회 화면 |
| 레시피 버전 기록 | 드로어(slide-in) | 편집 맥락 안 목록 참조 |
| 레시피 버전 미리보기 | 모달 | 편집 중 과거 버전 잠깐 비교(맥락 유지) |
| 삭제/중지/복원 확인 | 모달(`ConfirmModal`) | 짧은 yes/no 결정 |
| 사용자 생성 / 비밀번호 변경 | 모달 | 짧은 입력 폼 |
| 실행 확인(사이드 패널) | 모달 | 짧은 확인 |

## 오버레이 구현 규칙 (Base UI 래퍼로만)

> **모든 오버레이(모달·드로어·메뉴·툴팁)는 `packages/web/src/components/common/`의 앱 공통 래퍼로만 만든다.** 앱 코드에서 `@base-ui/react`를 직접 import 하거나, 오버레이 동작(포커스 트랩·ESC·바깥클릭·스크롤락·배경 inert·중첩 top-most·포커스 복귀)을 직접 구현하지 않는다.

### 래퍼 목록

| 오버레이 | 래퍼 | 기반 | 용도 |
|----------|------|------|------|
| 모달 | `AppModal` | Base UI Dialog | 확인/폼 등 모든 모달의 기반 |
| 확인 모달 | `ConfirmModal` | `AppModal` | yes/no 결정 (삭제·중지·복원·서비스 변경 등) |
| 드로어 | `AppDrawer` | Base UI Dialog | slide-in 참조 패널 (버전 기록 등) |
| 메뉴 | `AppMenu` | Base UI Menu | 드롭다운/드롭업 메뉴, 체크박스 다중선택, 옵션 선택 |
| 툴팁 | `AppTooltip` | Base UI Tooltip | hover/focus 보조 설명 |

### 규칙

- **직접 구현 금지**: `document.addEventListener("click"/"mousedown")` 기반 바깥클릭 닫기, 수동 Tab 포커스 트랩, `role="dialog"`/`aria-modal` 수동 지정, 자체 ESC 핸들러를 새로 만들지 않는다. 래퍼(Base UI)가 모두 처리한다.
- **시각은 디자인 토큰 유지**: 래퍼는 오버레이 *동작*만 Base UI에 위임하고, 시각은 기존 토큰 클래스(`.modal`, `.dropdown-menu` 등)를 그대로 입힌다. 새 오버레이도 토큰 클래스로 스타일한다.
- **중첩(nested) 오버레이**: 자식 오버레이(드로어 안의 미리보기/확인 모달 등)는 부모의 React 트리 *안에* 렌더한다. 그래야 Base UI가 중첩을 인식해 top-most만 ESC/바깥클릭을 받고, 배경 `aria-hidden`이 포커스 요소를 가리지 않는다. "열림 플래그를 형제로 띄우기"는 금지.
- **초기 포커스**: 폼 모달은 첫 입력(`initialFocusRef`), 위험 확인 모달은 취소 버튼(`initialFocus="cancel"`)에 최초 포커스를 둔다.
- **제어형 상태**: `open`/`onClose`(또는 `onOpenChange`)는 부모가 소유한다. 래퍼는 상태를 갖지 않는다.

## 페이지로 만들 때 지켜야 할 것

새 상세/편집 페이지는 [page-layout.md](./page-layout.md)의 상세/편집형 규칙을 따른다.

- `PageShell`로 감싸고 `PageActionBar`(뒤로가기 + 제목 + 우측 액션)를 상단 슬롯에 둔다. 제목 전용 헤더를 직접 마크업하지 않는다.
- 목록 → 상세 진입 시 **직전 목록 URL(필터 포함)을 전달**하고, 상세의 [← 목록으로]/브라우저 뒤로가기가 그 목록으로 복귀하게 한다(공통 헬퍼 사용). 딥링크 직접 진입 시 기본 목록 경로로 폴백.
- 404/삭제/권한 없음은 토스트가 아니라 **전용 빈 상태 화면 + [목록으로]** 로 처리한다(스펙 상세와 동일 패턴).
- 딥링크/새로고침 직접 진입을 고려해 **로딩 상태**를 표시한다.
