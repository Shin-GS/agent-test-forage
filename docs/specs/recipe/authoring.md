# 레시피 작성 UI/UX

## 작성 위치

- 별도 페이지 (`/recipes/new`, `/recipes/{id}/edit`): 넓은 화면에서 full form 편집
- 사이드 패널: 간단한 수정 시 (추후)
- 동일 컴포넌트를 양쪽에서 재사용

## 실행 아키텍처

레시피 실행 주체는 FE(사용자 브라우저). 외부 API 호출은 브라우저에서 직접.
- BE는 레시피 정의, 히스토리, AI 관리만 담당
- 방화벽 이슈 해결 (사용자 IP만 허용하면 됨)
- CORS는 client-spring 라이브러리에서 ai-test-forge 도메인 자동 허용

## 전체 구조

```
┌─────────────────────────────────────────────────────────────┐
│ 레시피 작성                                          [저장]  │
├─────────────────────────────────────────────────────────────┤
│ ① 메타 정보                                                 │
├─────────────────────────────────────────────────────────────┤
│ ② 사용자 입력 변수 (실행 전 액션 피커로 받을 값)               │
├─────────────────────────────────────────────────────────────┤
│ ③ 스텝 (필드 매핑 방식)                                      │
├─────────────────────────────────────────────────────────────┤
│ ④ 결과 정의 (실행 후 저장할 최종 값 + 템플릿에서 사용할 값)    │
├─────────────────────────────────────────────────────────────┤
│ ⑤ 결과 메시지 템플릿                                         │
└─────────────────────────────────────────────────────────────┘
```

## ① 메타 정보

| 항목 | UI | 필수 |
|------|------|------|
| 레시피명 | 텍스트 입력 | ✅ |
| 설명 | 텍스트 입력 | ✅ |
| 대상 서비스 | 드롭다운 (스펙 목록) | ✅ |
| 태그 | 태그 입력 (복수) | 선택 |
| 공개 범위 | 라디오 (공통/개인) | ✅ |

## ② 사용자 입력 변수

실행 전 액션 피커로 사용자에게 물어볼 값 정의. 레시피의 "파라미터".

```
변수명        │ 라벨       │ 타입         │ 필수 │ 기본값
──────────────┼───────────┼─────────────┼─────┼────────
productId    │ 상품 ID    │ [text ▾]    │ ✅  │
quantity     │ 수량       │ [number ▾]  │ ✅  │ 1
category     │ 카테고리    │ [select ▾]  │ ✅  │ food
[+ 추가]
```

- 각 항목별 기본값 설정 가능
- 자동 실행 모드: 사용자 미입력 시 기본값 사용
- 직접 입력 모드: 기본값이 미리 채워진 상태로 액션 피커 표시
- AI prefill: 대화 맥락에서 관련 값을 찾으면 기본값 대신 해당 값으로 세팅

## ③ 스텝 편집

### 핵심 원칙: 키보드 최소화, 마우스 선택 중심

스텝 편집 시 2단 레이아웃:

```
┌─── 스텝 설정 (좌) ────────────────┬─── 데이터 탐색기 (우) ─────────────┐
│                                   │                                   │
│ 스텝 설정 영역                     │ 📂 사용자 입력                     │
│                                   │   ├─ userInput.productId          │
│                                   │   └─ userInput.quantity           │
│                                   │                                   │
│                                   │ 📂 스텝 1: 회원 조회               │
│                                   │   ├─ memberId                    │
│                                   │   └─ memberName                  │
│                                   │                                   │
│                                   │ 📂 스텝 2: 상품 조회               │
│                                   │   ├─ price                       │
│                                   │   └─ stock                       │
│                                   │                                   │
│                                   │ ──────────────────────────────── │
│                                   │ 📋 현재 API 스키마                 │
│                                   │   요청: memberId(string,필수)...  │
└───────────────────────────────────┴───────────────────────────────────┘
```

- 현재 스텝보다 위 모든 스텝의 extract된 변수 표시
- 변수 클릭 → 좌측 매핑에 삽입
- 변수는 뱃지/태그로 시각 구분

### API 타입 — 요청 필드 매핑

API 선택하면 스키마에서 요청 필드가 자동 나열 (키보드 0):

```
요청 필드        │ 값 소스              │ 매핑 값
────────────────┼─────────────────────┼──────────────────
memberId *      │ [이전 스텝 결과 ▾]    │ [스텝1 > memberId ▾]
productId *     │ [사용자 입력 ▾]       │ [userInput.productId ▾]
quantity        │ [직접 입력 ▾]         │ [___1___]
memo            │ [AI 생성 ▾]          │ (자동)
```

값 소스 4종:

| 값 소스 | 설명 | 매핑 값 UI |
|---------|------|-----------|
| 이전 스텝 결과 | extract된 변수 | 드롭다운 (스텝 > 변수명) |
| 사용자 입력 | 사용자 입력 변수(②) | 드롭다운 (userInput.xxx) |
| 직접 입력 | 고정값 (유일하게 키보드 필요) | 텍스트 입력 + 타입 검증 |
| AI 생성 | AI가 실행 시 자동 생성 | 없음 |

**"AI 생성" 동작 상세**: 실행 시 AI에게 아래 정보를 전달하여 적절한 값을 생성:
- 필드명 + 타입 (스키마에서)
- 해당 API의 description (스펙)
- 레시피의 AI 힌트 (작성자가 입력한 경우)
- 이전 스텝 context (맥락 참조)

### 중첩 객체 처리

트리형으로 들여쓰기하여 플랫하게 나열:

```
address
  ├ city          │ [직접 입력 ▾] │ [서울]
  └ zipCode       │ [직접 입력 ▾] │ [12345]
items[0]
  ├ name          │ [사용자 입력 ▾] │ [...]
  └ quantity      │ [직접 입력 ▾] │ [1]
  [+ 항목 추가]
```

- 배열: `items[0]`, `items[1]` 식으로 행 세트 복제 가능
- 전체 배열을 이전 스텝에서 통째로 가져오기도 가능:
  ```
  items │ [이전 스텝 결과 (전체 배열) ▾] │ [스텝2 > items ▾]
  ```

### API 타입 — Extract (응답값 추출)

```
변수명     │ 추출 방식        │ 값
──────────┼────────────────┼───────────────
orderId   │ [JSONPath ▾]   │ [$.orderId ▾] [✏️ 직접 입력]
message   │ [전체 응답 ▾]    │ (전체 텍스트)
code      │ [상태 코드 ▾]   │ (HTTP status)
[+ 추가]
```

추출 방식:

| 방식 | 설명 | 값 지정 |
|------|------|---------|
| JSONPath | JSON 응답에서 필드 추출 | 스키마 있으면 드롭다운, 없으면 직접 입력 |
| 전체 응답 | 응답 body 전체 텍스트 | 불필요 |
| 상태 코드 | HTTP status code | 불필요 |
| 헤더 | 응답 헤더 값 | 헤더 이름 |

- 스키마 있으면: 드롭다운 (타이핑 0)
- 스키마 없으면: 자동으로 직접 입력 모드
- [✏️] 토글: 스키마 있어도 직접 입력으로 전환 가능

### 배열 응답 항목 접근

```
소스: [스텝2 > members ▾]
접근: [첫 번째 항목 ▾]
      ─────────────
      첫 번째 항목
      마지막 항목
      인덱스 지정 (직접 입력)
      전체 배열
```

### 스크립트 타입

```
사용할 변수 (context에서 가져올 것)
──────────────────────────────────
☑ memberId (스텝1)
☑ userInput.productId
☐ Step0 (전체 응답)

코드:
┌────────────────────────────────────┐
│ function execute(context) {        │
│   return { summary: "..." };       │
│ }                                  │
└────────────────────────────────────┘

출력 변수 정의:
변수명        │ 설명
──────────────┼──────────────────
summary      │ 요약 문자열
totalPrice   │ 계산된 총 금액
[+ 추가]
```

- 입력: 체크박스로 사용할 변수 선택
- 코드: textarea + 구문 하이라이팅 (추후 Monaco)
- 출력: 사용자가 명시적으로 선언 → 다음 스텝에서 참조 가능

### 서브레시피 타입

```
대상 레시피: [회원가입 ▾]

입력 매핑 (서브레시피의 사용자 입력 변수):
서브레시피 변수  │ 값 소스           │ 매핑 값
───────────────┼──────────────────┼──────────────
email *        │ [이전 스텝 결과 ▾] │ [스텝1 > email ▾]
password *     │ [직접 입력 ▾]      │ [test1234]
```

- 서브레시피의 ② 사용자 입력 변수가 입력 스키마
- 서브레시피의 ④ 결과 정의가 출력 → 데이터 탐색기에서 참조 가능
- 결과 정의 없으면 출력 참조 불가 (경고 표시는 참조하려 할 때만)

### 조건 (condition) 빌더

각 스텝에 선택적으로 조건 추가:

```
조건: [스텝1 > statusCode ▾] [== ▾] [401]
```

| 연산자 | 설명 |
|--------|------|
| == | 같음 |
| != | 다름 |
| > | 초과 |
| < | 미만 |
| contains | 포함 |
| exists | 값이 있음 |
| not exists | 값이 없음 |

- 조건 만족 → 스텝 실행
- 조건 불만족 → 스킵

## ④ 결과 정의

실행 후 서버에 저장할 최종 값. 히스토리 표시, 다음 레시피에서 참조, 템플릿에서 사용.

```
변수명        │ 소스
──────────────┼──────────────────
orderId      │ [스텝3 > orderId ▾]
jobTitle     │ [스텝1 > title ▾]
memberName   │ [스텝1 > memberName ▾]
[+ 추가]
```

- 드롭다운으로 스텝 > 변수 선택 (키보드 불필요)
- 결과 정의에 등록해야 ⑤ 템플릿에서 사용 가능
- 서브레시피로 호출될 때 이게 부모에게 전달되는 출력

## ⑤ 결과 메시지 템플릿

레시피 성공 완료 시 사용자에게 보여줄 메시지:

```
[주문이 생성되었습니다.
 - 주문번호: [orderId]
 - 상품: [jobTitle]
 - 수량: [userInput.quantity]          ]
```

- 사용 가능한 변수: ④ 결과 정의 변수 + ② 사용자 입력 변수
- 변수는 뱃지/태그로 시각 표시, 클릭으로 삽입
- 미입력 시 AI가 자동 요약
- 채팅 완료 메시지 + 히스토리 요약에 사용됨

## 유효성 검증

저장 시 자동 검증:

| 항목 | 설명 |
|------|------|
| 필수 필드 미매핑 | 요청 필드 중 필수(*)인데 값 소스 미선택 |
| 타입 불일치 | number 필드에 문자열 직접 입력 등 |
| 존재하지 않는 변수 참조 | 삭제된 스텝의 변수를 참조 |
| 순환 참조 | 서브레시피가 서로를 호출 |
| 스펙 호환성 | API가 스펙에 존재하는지 |
| 순서 변경 후 참조 깨짐 | 참조 대상이 현재 스텝보다 아래에 있음 |
