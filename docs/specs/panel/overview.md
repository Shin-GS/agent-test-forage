# 사이드 패널

## 개요

우측에 위치하는 **독립 미니 페이지 모듈**. 채팅과 분리되어 자기 데이터를 스스로 조회한다.

- 채팅은 SSE + 통합 상태로 동작하지만, 패널의 각 뷰는 **일반 웹페이지처럼 REST API로 자기 데이터를 가져온다**(커서 기반 무한스크롤).
- 패널 데이터는 채팅 상태와 **분리**한다.
- 채팅 ↔ 패널 연동은 느슨하게만 유지한다: **실행 완료 시 히스토리 갱신 신호(무효화)** 정도.

## 패널 구조

우측 패널은 위에서부터 **[대상 서비스 블록(최상단 고정)] → [홈/레시피/히스토리 탭] → [탭 내용]** 순서로 구성한다. (기존 전역 상단 헤더 바 및 채팅 헤더의 서비스 표시는 폐지되고, 대상 서비스는 이 블록으로 이동했다 — [chat/overview.md 대화방 서비스 설정](../chat/overview.md#대화방-서비스-설정))

## 대상 서비스 블록 (최상단 고정)

현재 대화방의 **대상 서비스(`apiSpecId`)**를 표시·선택·변경하는 고정 블록. 탭 위에 항상 표시된다.

### 상태 2가지

| 상태 | 표시 | 비고 |
|------|------|------|
| 지정됨 | `🏷️ 대상 서비스: {서비스명} ▾` | ▾ 클릭으로 드롭다운 변경 |
| 미지정 | `🏷️ 서비스 선택 안 됨 ▾` | **중립적 표시**(은은한/중립 색). 오류가 아니라 **정상 기본 상태** — 경고색(⚠️) 아님. **새 대화 기본값** |

- 미지정은 **에러/경고 상태가 아니라 정상 기본 상태**다. 경고 아이콘·경고색을 쓰지 않고 중립 톤으로 표기한다.

### 드롭다운 / 변경

- 드롭다운 목록은 `GET /api/v1/specs`로 조회한다. 옵션 라벨은 **`serviceDescription` 우선, 없으면 `name`**.
- 판정 주체는 **FE**, 기준은 **`conversationId` 유무**다([chat/overview.md 서비스 변경 안전 규칙](../chat/overview.md#서비스-변경-안전-규칙)).
- **새 대화(`conversationId` 없음, 서버 미생성)**: 확인 없이 자유롭게 변경. 선택값은 **FE 로컬 pending**에 보관되고, 첫 메시지 전송 시 대화방 생성에 반영된다([chat/overview.md 새 대화의 선택 서비스 보관](../chat/overview.md#새-대화의-선택-서비스-보관-pending)). 표시값은 pending 값.
- **이미 생성된 대화(`conversationId` 있음)**: 선택 시 **변경 확인 모달** 노출 → 확정 시 서비스 변경 API 호출. 과거 실행 히스토리는 유지. 표시값은 대화방 `apiSpecId`.
  - 확인 모달 문구: "대상 서비스를 바꾸면 이후 레시피 매칭에 영향을 줍니다. 과거 실행 기록은 유지됩니다. 계속하시겠어요?"
  - 변경 성공 시 서버가 `session_list_update`(op=`upsert`)로 목록 배지·active 서비스를 **모든 탭에 동기화**한다([messaging.md 대화방 목록 갱신](../common/messaging.md#대화방-목록-갱신-session_list_update)).
- **경계 케이스 없음**: 빈 대화방은 orphan 차단으로 서버에 존재하지 않으므로 "메시지 0건인 생성된 대화"는 없다.

### 접힘 폴백

- 패널이 접힘/오버레이로 이 블록이 보이지 않을 때는, **좌측 대화 목록의 현재(active) 대화 서비스 배지**로 대상 서비스를 확인한다(배지 시인성 강화). 상세: [chat/overview.md 대화방 목록 상태](../chat/overview.md#대화방-목록-상태)
- 이 폴백은 **서비스 확인(표시)만** 제공한다. **변경하려면 패널을 펼쳐야 한다**(의도된 제약).

### BE 계약 영향

- 서비스 변경은 **신규 API** `PATCH /api/v1/conversations/{id}/service`(body `apiSpecId`)를 사용한다(BE 추가 예정).

### 서비스 독립 (탭과 분리)

- **대상 서비스 블록은 "이 대화의 실행 대상"만 결정**한다. 아래 레시피/히스토리 탭의 **자체 서비스 필터와는 독립**이며, 탭은 자유롭게 다른 서비스를 탐색할 수 있다(b안).

## 탭 구성

상단 가로 탭 3개. 선택한 탭이 패널 전체를 차지한다. 각 탭 내부 상세는 **스택 드릴다운(뒤로가기)**로 연다.

| 탭 | 역할 |
|------|------|
| 홈 (기본) | 요약 대시보드 |
| 레시피 | 레시피 탐색/실행 |
| 히스토리 | 실행 이력 조회 |

### 홈 (기본 탭)

요약 대시보드. 두 섹션으로 구성.

- **자주 쓴 레시피**: 사용 빈도 / 최근 사용순 3~5개 (레시피 요약의 `usageCount` / `lastUsedAt` 기준 정렬 — 즐겨찾기 없이 산출)
- **최근 실행**: 최근 실행 3~5건
- 각 섹션에 **[전체 →]** 링크로 해당 탭(레시피 / 히스토리)으로 이동
- 즐겨찾기는 2차 — 데이터 준비되면 "자주 쓴" 옆 또는 대체로 추가

### 레시피 탭

- **서비스 선택 드롭다운**: 탐색 전용이며 대화방 서비스와 **독립**. 옵션 라벨은 사람이 알아보기 쉽게 **"서비스 설명 (기술명)"** 형태(예 "온라인 쇼핑몰 (demo-shop)"). 설명이 없으면 기술명만. 선택된 서비스 영역에 설명 + 도메인(작은 폰트) 노출.
  - 탐색 중 대화방 서비스와 다른 서비스의 레시피를 [▶] 실행하면, 발화+참조 태그로 채팅 flow를 타며 이때 AI가 서비스 불일치를 감지해 **서비스 변경을 확인**한다([chat/overview](../chat/overview.md) 서비스 매칭 정책 준수). 패널이 대화방 서비스를 임의로 바꾸지 않는다.
- **검색**: name / desc 대상, 디바운스 적용
- **필터**: [전체] [내 레시피] [공통]
- **목록**: 커서 무한스크롤. 1차 정렬은 **사용 빈도순**
- 항목 표시: 레시피명 + [서비스 배지] + **설명 1줄**(작은 폰트, 말줄임) + 사용정보(🕒 최근 사용 상대시각 · N회) + [▶](실행)

### 히스토리 탭

- 실행 이력 전체를 커서 무한스크롤로 표시
- 항목 = [상태 아이콘] 레시피명 / 🌐 **서비스명** · 결과 요약 / **상대시각 · 소요시간**
  - 상태 아이콘: 성공 ✅ / 부분성공 ⚠️ / 실패 ❌ / 중지·취소 ⏹️ (messaging.md 종료 사유 SUCCESS/PARTIAL/FAILED/STOPPED/CANCELLED 대응)
  - 서비스명: 실행의 대상 서비스명(설명 우선). 플랜 등 단일 서비스가 아니면 **"여러 서비스"**
  - 상대시각: "N분 전/시간 전/어제/날짜". 소요시간: durationMs 표기(없으면 생략)
- 항목 클릭 시 결과 상세로 드릴다운 (2차)

## 실행 공통화

레시피 [▶] 및 히스토리 재실행은 **직접 실행이 아니다.**

### 실행 전 확인 모달 (오클릭·탐색 케이스 방어)

패널 목록에서 [▶]를 누르면 **바로 발화를 전송하지 않고, 먼저 확인 모달을 연다.** 사용자가 "이게 무슨 레시피인지 눌러보는" 탐색 케이스나 스크롤 중 오클릭이 곧바로 실행 개시로 이어지지 않게 하는 완충 단계다.

- **적용 대상**: 홈 탭 "자주 쓴 레시피" [▶], 레시피 탭 목록 [▶], **히스토리 재실행 [▶]** 모두.
- **모달 구성**: 레시피명 + [서비스 배지] + 설명 1줄(패널 목록의 설명 재사용) + `[취소]` / `[실행]` **2개 버튼만**. 제목 문구는 진입에 따라 분기한다: 레시피/홈 탭 [▶]는 **"이 레시피를 실행할까요?"**, 히스토리 [▶]는 **"이 레시피를 다시 실행할까요?"**.
- 재사용 컴포넌트 **ConfirmModal** 사용(삭제 확인과 동일 컴포넌트). **ESC / 배경 클릭으로 취소**, focus trap 적용. 위험 액션 아님(중립 톤 — 삭제처럼 빨강 아님). **오클릭 방어가 목적이므로 초기 포커스는 [취소]**에 둔다(Enter로 곧장 실행되지 않게).
- **[취소]** → 아무 동작 없음(대화방 그대로). ESC/배경 클릭도 취소로 귀결. 탐색 목적 사용자는 여기서 내용만 확인하고 닫는다.
- **[실행]** → 아래 기존 동작(발화 + 참조 태그 전송)으로 진입한다. **이 모달은 "실행 준비(발화 전송) 시작 여부"를 묻는 것**이고, 실제 스텝 실행 방식(바로 실행/값 확인 후 실행) 선택은 뒤이어 뜨는 채팅 카드에서 한다 — 아래 [카드와의 층위 구분] 참조.
- **히스토리 재실행은 재개(resume)가 아니라 신규 실행**이다: 이전 실행을 이어가는 것이 아니라 같은 레시피를 새 발화로 처음부터 실행한다(STOPPED/PARTIAL의 [이어서 실행] 재개 경로와 다름).

#### 확인 모달과 실행 카드의 층위 구분 (이중 확인 아님)

패널 확인 모달과 채팅 카드의 [바로 실행]은 **서로 다른 층위**이며 이중 확인이 아니다. 어느 한쪽을 생략하지 않는다.

- **패널 확인 모달** = "이 레시피로 **실행 흐름을 시작(발화 전송)할지**" — 목록에서의 오클릭·탐색 방어(대화방에 개입이 시작되기 전 단계).
- **채팅 카드 [바로 실행]/[값 확인 후 실행]** = 흐름이 시작된 뒤 "**스텝을 어떤 방식으로 실행할지**"(입력값 확인 여부) 선택([card-ui.md 실행 모드형](../chat/card-ui.md#유형)).
- 두 단계는 대상이 다르다(발화 전송 여부 ↔ 실행 방식). 채팅에서 사용자가 직접 발화로 실행할 때는 패널 모달 단계가 없고 카드만 거친다.

### 실행 동작

- 동작: **현재 대화방에 "XX 레시피 실행하기" 발화 + 참조 태그(referenceId = recipeId) 전송**
- 이후 정상 채팅 실행 flow(AI `execute_recipe` → 카드 → 실행)를 그대로 탄다.
- 히스토리 재실행도 동일 방식(재실행도 확인 모달을 먼저 거친다).
- **서비스 불일치**: 대화방 서비스와 다른 서비스 레시피를 실행하면, 실행 확인 모달과 **별개로** 발화 전송 후 AI가 서비스 변경을 확인한다(두 확인은 성격이 달라 중복이 아님 — 전자는 "실행 의도", 후자는 "서비스 변경").
  - **순서**: ① 패널 확인 모달 [실행] → ② 발화+참조태그 전송(대화에 남음) → ③ AI가 서비스 불일치 감지 → 서비스 변경 확인(clarify류) 응답.
  - **변경 거부 시**: ②에서 발화는 이미 전송됐으므로 되돌리지 않는다. AI는 서비스를 바꾸지 않고, 현재 서비스 기준으로 매칭 실패면 `no_match`(또는 `clarify`)로 안내한다(대화방 서비스는 유지). 즉 "실행되지 않고 안내로 종료"된다.
- **대화방 락 안내**: 대화방이 처리 중(AI 응답 / 실행 / 입력 대기)이면 [▶]는 비활성 + 툴팁("실행 중에는 사용할 수 없어요")으로 이유를 표시한다(비활성이라 확인 모달도 열리지 않는다). 카드의 [바로 실행]/[값 확인 후 실행]은 처리 중 클릭 시 토스트로 안내하고 막는다. 락 경합(BE 409 CONVERSATION_BUSY)도 동일 토스트로 폴백한다.

## 접기 / 리사이즈 (1차)

우측 패널의 접기·리사이즈를 **1차 범위로 승격**한다(기존 2차에서 상향).

- **완전 접기**: 패널을 완전히 접을 수 있다. 접힌 상태에서는 **우측 가장자리에 펼치기 핸들(◀)**을 노출해 다시 펼친다
- **리사이즈**: 패널 **좌측 경계선을 드래그**해 폭을 조절. 최소/최대 폭으로 **clamp**(중앙 채팅 최소 폭 침범 금지). 드래그 중 구분선 하이라이트(accent-subtle)
- **항상 우측 가장자리에 고정(앵커)**: 패널은 **뷰포트 오른쪽 끝에 붙어 있어야 한다**. 리사이즈는 **폭만** 바꾸고 우측 앵커는 유지한다. 창 크기가 바뀌어도(더 넓은 화면/최대화) 패널이 오른쪽에서 떨어져 여백이 생기거나, 반대로 화면 밖으로 넘쳐 잘리면 안 된다.
  - 레이아웃 원칙: 패널은 3열(사이드바 / 중앙 채팅 / 패널) 중 **마지막 열**이며, 폭은 clamp된 값, **중앙 채팅이 남는 공간을 모두 흡수**(flex-grow)한다. 패널을 고정폭 + 우측 앵커로 두고 중앙을 가변으로 두면 어떤 창 폭에서도 패널이 우측에 붙는다.
  - **가용 폭 기준 재-clamp(넘침 방지)**: 패널 폭은 `min(저장폭, 가용폭 − 사이드바 − 중앙 채팅 최소폭)`으로 **매 렌더/창 리사이즈 시 다시 clamp**한다. 저장값이 현재 뷰포트에 과도하면 그 값을 강제하지 말고 축소한다(중앙 채팅 최소폭 침범·패널 넘침 방지). **중앙 채팅 최소폭이 우선**한다.
  - **폭 적용은 CSS 변수로**: 패널 폭은 인라인 px가 아니라 **CSS 변수**(예 `--panel-width`)로 관리한다. 리사이즈 드래그 중에는 이 변수만 갱신(리렌더 없이 부드럽게)하고, 최종 값만 localStorage에 저장한다. 리사이즈 중에는 폭 `transition`을 끄고(끊김 방지), 접기/펼치기 애니메이션에만 transition을 적용한다.
  - **구분선 더블클릭 = 기본 폭 리셋**: 리사이즈 구분선을 더블클릭하면 패널 폭을 기본값으로 되돌린다(과도하게 넓혀 중앙이 눌린 상태를 빠르게 복구).
- **자동 오버레이 임계는 가용 폭 부족 기준**: 단순 뷰포트 px 하드코딩(1200)만으로 판정하지 않고, **`사이드바 + 중앙 채팅 최소폭 + 패널 최소폭`을 확보할 수 없으면** 패널을 오버레이로 전환한다(넓게 리사이즈한 상태에서도 넘치지 않게). px 임계값은 이 계산의 근사 기본값으로 유지한다.
- **localStorage 저장**: 접힘/펼침 상태와 너비를 저장해 새로고침·재방문 시 복원(저장값도 로드 시 위 재-clamp 적용)

## 반응형

| 뷰포트 | 동작 |
|------|------|
| Desktop (넓음) | 채팅 옆 고정 열, 항상 열림 |
| Tablet (중간) | 기본 닫힘, 토글로 오버레이 |
| Mobile (좁음) | 전체화면 시트 (채팅과 전환) |

### 반응형 자동 접기

- **중앙 채팅 최소 폭 480px를 항상 보장**한다(단, 모바일 전체화면 시트 모드는 예외 — 아래)
- **우측 패널 자동 오버레이 판정은 "가용 폭 부족" 기준**이다: `사이드바 + 중앙 채팅 최소폭 + 패널 최소폭`을 확보할 수 없으면 우측 패널을 먼저 오버레이로 전환한다. 뷰포트 **< 1200px**는 이 계산의 **근사 기본 임계값**이며(패널을 넓게 리사이즈한 상태에서도 넘치지 않게), px는 구현 시 미세조정 가능
- 뷰포트 폭 **< 768px**이면 좌측 사이드바도 아이콘 레일/오버레이로 전환 (레이아웃 상세: [chat/overview.md 반응형 자동 접기](../chat/overview.md#반응형-자동-접기))
- **모바일(뷰포트 < 480px)**: 중앙 채팅 480px 보장 규칙을 무력화하고, 우측 패널은 **전체화면 시트**(채팅과 전환)로 전환한다. 세 열을 나란히 두지 않고 단일 컬럼으로 동작한다
- 우선순위: **우측 먼저, 그다음 좌측**

## Empty State

| 조건 | 표시 |
|------|------|
| 레시피 0개 | "아직 레시피가 없어요. 관리자에게 요청하거나 직접 만들어보세요." |

| 해당 서비스 레시피 0개 | "이 서비스(XX)에 등록된 레시피가 없어요." |
