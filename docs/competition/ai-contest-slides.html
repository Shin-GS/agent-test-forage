내용

반복되는 테스트 데이터 준비를 대화 한 번으로

문제

QA는 테스트마다 상황에 맞는 데이터를 직접 만듭니다. 어떤 API를 어떤 순서로 호출할지, 관련 정책이 무엇인지 알아야 하고, 경우의 수가 많아 매번 반복됩니다.

해결

채팅으로 원하는 상황을 말하면 AI가 필요한 API를 골라 실행해 데이터를 만듭니다. DB를 직접 건드리지 않고 실제 API로만 만들기 때문에 현실과 같은 데이터가 안전하게 나옵니다.

핵심 — 미리 짜두는 게 아니라, 처음 보는 요청도 그 자리에서 API를 조합해 실행합니다.

실제 화면 — “회원가입 테스트 데이터 3건 만들어줘” → AI가 레시피를 실행
02 / 06
예시 시나리오

여러 서버를 넘나들며, 한 문장으로 끝낸다

“ 운영 중인 공고 아무거나 골라서 지원하고, 서류 합격까지 만들어 줘 ”
사용자용 서버
1 회원가입 또는 기존 계정 로그인
2 메일 인증번호를 스크립트로 읽어 인증
3 운영 중인 공고 중 하나 탐색
4 해당 공고에 입사지원
기업용 서버
5 방금 생성된 지원 건을 서류 합격 상태로 변경
결과 → 지원자 계정 · 지원한 공고 · 서류 합격 상태까지 한 번에 준비
이 시나리오가 보여주는 것

하나의 서버로 끝나지 않습니다. 사용자용 서버와 기업용 서버를 넘나들며 순서대로 실행합니다. 사람이 하면 여러 화면을 오가야 하는 일을 한 문장으로 끝냅니다.

스크립트의 역할

2번의 메일 인증번호 읽기처럼, API 호출만으로는 막히는 중간 단계도 스크립트가 처리해 흐름이 끊기지 않습니다.

왜 이 도구가 강력한가

⚡

즉석 조합

처음 보는 요청도 필요한 API를 그 자리에서 조합해 실행합니다. 미리 짜둘 필요가 없습니다.

🛡️

DB를 안 건드림

실제 API로만 만들어 안전하고, 현실과 동일한 데이터가 나옵니다.

✅

지어내지 않음

실제 API 목록과 Jira 문서를 근거로만 답하고 실행합니다. 위험한 작업은 실행 전 확인을 받습니다.

🧩

블록처럼 조합

API 호출 · 다른 레시피 · 스크립트를 묶습니다. 메일 인증 같은 중간 단계까지 이어집니다.

🔌

붙이면 연동

서버에 라이브러리만 추가하면 그 서버의 API 목록을 자동으로 수집·등록합니다.

🔑

내 권한으로 실행

브라우저가 직접 호출합니다. 시스템이 남의 인증 정보를 들고 있지 않습니다.

AI 활용 내용 · 동작 원리

왜 굳이 AI인가

1말을 이해해 실행 — 요청을 이해해 필요한 API를 골라 순서대로 조합·실행합니다.
2스스로 찾아 보완 — 부족한 정보는 실제 API 목록과 Jira 문서를 스스로 찾아 채웁니다.
WHY AI?

요청이 매번 다르고 상황 판단이 필요합니다. 정해진 규칙 기반 자동화로는 안 됩니다. 그때그때 이해하고 조합하는 일은 AI만 할 수 있습니다.

준비
각 서버에 라이브러리를 붙이면 API 목록이 자동 등록됩니다. (개발·STG 환경에서만 전송)
사용
사용자가 말함 → AI가 필요한 API 선택 (레시피 / 플랜) → 브라우저에서 직접 호출 → 결과 정리
보안 — 라이브러리를 설정 파일로 활성화해야 동작하고, API 목록은 개발·STG 환경에서만 전송하므로 운영 환경에는 영향을 주지 않습니다.
실행 결과 요약 — 스텝별 성공/실패까지 한눈에 정리

그 외 · 비전

QA 데이터 생성은 시작점입니다

01

이슈 / VOC 재현

티켓이 올라오면 그 티켓을 재현할 데이터를 자동으로 만들어 둡니다. 개발자는 재현된 상태에서 바로 확인합니다.

02

미니앱형 통합 플랫폼

사이드 패널 입력 폼을 갖추면 여러 서버를 한곳에서 다루는 통합 플랫폼으로 확장됩니다.

03

대화형 어드민

관리자가 화면을 찾아다니지 않고 말로 조회·처리합니다.

04

확장 기능

프로토타입 완성 후 데이터 되돌리기, 같은 상황 대량 생성, 레시피 공유 등으로 넓힐 수 있습니다.

지금은 QA 테스트 데이터 생성에 집중하지만,
같은 구조를 사내 여러 서버의 반복 업무로 넓혀갈 수 있습니다.
