# ai-test-forge 기획 정리

## 1. 프로젝트 개요

AI 기반 API 워크플로우 실행 플랫폼. 사용자가 채팅으로 의도를 전달하면 AI가 적절한 레시피를 찾아 실행하고, 결과를 보여준다.

**핵심 원칙**: 모든 API 호출은 반드시 레시피를 통해서만 수행한다.

---

## 2. 용어 정의

| 용어 | 정의 |
|------|------|
| **레시피** | 작업의 실행 순서를 정의한 워크플로우. 순차 실행되는 스텝의 집합 |
| **스텝** | 레시피 내 개별 실행 단위. 타입: API 호출 / 스크립트(JS) |
| **액션 피커** | 채팅 input 영역에 겹쳐 노출되는 구조화된 입력 UI. 취소 버튼 상시 노출 |
| **사이드 패널** | 우측에 위치하는 다목적 영역. 레시피 목록, 히스토리, 실행 결과 상세, 레시피 작성 등 |
| **카드 UI** | 대화 영역에 삽입되는 시각적 블록. 사이드 패널의 상세 뷰를 여는 진입점 |
| **작업 히스토리** | 레시피 실행 이력. 사이드 패널 내에서 레시피 목록과 함께 표시 |
| **스펙** | 외부 서버의 OpenAPI 스펙. 레시피에서 호출 가능한 API 목록의 원천 |
| **인증 프로필** | 외부 서버의 로그인 정보. name + loginPageUrl |
| **참조 태그** | 채팅 input 상단에 표시되는 현재 패널 컨텍스트 표시. AI에게 레시피 ID 등을 함께 전달 |

## 3. 인터페이스 구조

```
┌─────────┬──────────────────────────┬───────────────────────────┐
│ 사이드바  │   대화 영역 (중앙)         │   사이드 패널 (우)          │
│         │                          │                           │
│ 대화 목록 │  사용자 ↔ AI 대화         │  레시피 목록               │
│ (삭제 가능)│  + 카드 UI              │  + 히스토리                │
│         │  + 액션 피커 (input 위치)  │  → 상세 보기 (스택)        │
│         │                          │  → 레시피 작성 (추후)       │
└─────────┴──────────────────────────┴───────────────────────────┘
```

### 3.1 사용자 입력 수단

- **채팅 Input** — 자유 텍스트 입력
- **액션 피커** — 구조화된 입력 (input 영역에 겹쳐 노출)

### 3.2 사이드 패널

채팅과 동시에 봐야 하는 가벼운 정보를 보여주는 보조 창. 첫 진입 시 기본 열림.

#### 패널에 적합한 것 (채팅 맥락에 종속된 가벼운 조회)
- 레시피 실행 결과 보기
- 레시피 간략 보기 (스텝 구성 확인)
- 히스토리 미리보기 (최근 실행 건)
- 레시피 목록 탐색

#### 별도 페이지로 분리할 것 (독립적이고 무거운 작업)
- 레시피 상세 작성/편집 (full form)
- 전체 히스토리 목록 (검색, 필터)
- 스펙 관리
- 설정
- 대시보드

#### 패널 기본 화면
- 레시피 목록 (정렬 우선순위: 이 대화에서 사용 > 즐겨찾기 > 개인 > 공통)
- 히스토리 최근 건

#### 상세 뷰 (스택)
- 레시피 상세: 스텝 구성 보기
- 실행 결과 상세: 뷰 타입(읽기 전용) / 에디터 타입(수정 가능 form)

#### 동작 규칙
- 레시피 실행 완료 시: 히스토리 목록 refresh (최신 건 상단)
- 카드 UI [결과 보기] 클릭: 패널에서 해당 결과 상세로 전환
- 레시피 목록 항목 클릭: 레시피 상세 뷰로 진입
- 뒤로가기: 이전 뷰로 복귀

### 3.3 패널 컨텍스트 전달 (참조 태그)

```
┌─────────────────────────────────────────────────┐
│  📎 주문 생성 레시피 참조 중          [✕ 해제]   │
├─────────────────────────────────────────────────┤
│  메시지를 입력하세요...                           │
└─────────────────────────────────────────────────┘
```

- 사이드 패널에서 레시피를 열면 참조 태그 자동 표시
- 채팅 전송 시 해당 ID가 함께 전달됨 (AI 의도 매칭 보조)
- [✕] 또는 패널 닫기/다른 뷰 전환 시 자동 해제

### 3.4 작업 히스토리

- 레시피 실행 건만 저장
- 대화방 삭제해도 히스토리는 독립적으로 유지
- 표시 정보: 실행 시각, 레시피명, 생성된 데이터, 성공/실패
- 항목 클릭: 사이드 패널에서 실행 결과 상세 보기

## 4. 핵심 플로우

### 4.1 레시피 실행

```
사용자 발화 (채팅)
    │
    ▼
AI 의도 분석 → 레시피 매칭 (참조 태그 있으면 우선 참조)
    │
    ├─ 매칭됨 → 레시피 간략 설명 + 필요 데이터 요청 (액션 피커)
    │            ├─ 입력 완료 → 실행 승인 요청
    │            │              └─ 승인 → 실행 → 완료 메시지 + 카드 UI
    │            │                                └─ [결과 보기] → 사이드 패널 상세
    │            └─ 취소 → AI "취소되었습니다" 응답 → 자유 대화 복귀
    │
    └─ 매칭 안 됨 → "해당 레시피가 없습니다. 레시피를 생성해주시면 좋겠습니다" 안내
                    (추후: "생성하시겠어요?" → 대화로 레시피 생성)
```

### 4.2 인증 필요 시

```
레시피 실행 중 401/403 감지
    │
    ▼
카드 UI:
  [로그인하러 가기]  → 새 탭으로 loginPageUrl
  [로그인 완료]     → 중단된 스텝부터 재개
                     └─ 여전히 401/403 → "로그인이 처리되지 않은 것 같습니다.
                                          다시 로그인 부탁드립니다." + 같은 카드 재노출
```

### 4.3 액션 피커 동작 규칙

- AI가 액션 피커를 띄우는 질문 → 사용자가 답변하지 않은 상태에서만 유효
- 사용자가 채팅 input으로 직접 메시지를 보내면 → 액션 피커 자동 닫힘
- 취소 클릭 → AI "취소되었습니다" 응답 → 채팅 input 복귀

### 4.4 대화 내 연속 실행

- 하나의 대화에서 여러 레시피를 연속 실행 가능

### 4.5 에러 처리

스텝 실행 중 에러(500, 타임아웃 등) 발생 시:
- 진행 상태에서 해당 스텝을 ❌ 표시
- AI가 "스텝 N에서 실패했습니다" 메시지 출력
- 카드 UI로 [다시 실행] 버튼 표시 (실패한 스텝부터 재개)

### 4.6 AI 의도 매칭이 애매할 때

유사 레시피가 여러 개 매칭될 때 카드 UI로 후보 목록 표시:

```
AI: 요청하신 내용과 비슷한 레시피가 여러 개 있어요.

  1. 입사지원 (사람인)
     "사람인 채용공고에 이력서 제출"

  2. 입사지원 (잡코리아)
     "잡코리아 채용공고에 이력서 제출"

  3. 입사지원 (자체 ATS)
     "내부 채용시스템에 지원"

  [없으면 다시 설명할게요]
```

- 클릭하면 해당 레시피 실행 플로우 진입
- 후보 5개 이상 시 상위 3개만 표시 + "더보기" → 사이드 패널 레시피 목록으로 유도

## 6. 레시피 구조

### 6.1 소유 구분

- **공통 레시피** — 관리자가 생성, 모든 사용자에게 노출
- **개인 레시피** — 본인만 사용

### 6.2 메타 정보

| 항목 | 설명 | 필수 |
|------|------|------|
| 레시피명 | 식별 + AI 매칭용 | ✅ |
| 설명 | AI 의도 매칭에 활용 | ✅ |
| 대상 서비스 | 어느 사이트를 위한 레시피인지 (단일 선택) | ✅ |
| 태그 | 분류/검색/필터용 (복수 입력) | 선택 |
| 공개 범위 | 공통 / 개인 | ✅ |
| 사용자 입력 변수 | 실행 시 사용자에게 물어볼 데이터 | 선택 |
| 스텝 목록 | 실행할 작업 순서 | ✅ |

### 6.3 스텝 타입

| 타입 | 역할 |
|------|------|
| **API** | 외부 서버 API 호출 |
| **스크립트** | JavaScript 실행 (데이터 가공, 조건 판단) |
| **레시피** | 다른 레시피를 서브레시피로 호출 |
| **사용자 입력** | 실행 중 사용자에게 데이터 요청 (액션 피커) |

#### API 타입

| 항목 | 설명 |
|------|------|
| 스텝명 | 식별용 |
| 대상 서브도메인 | 스펙 목록에서 선택 |
| API | method + path (스펙에서 선택) |
| Body | 요청 본문 (변수 바인딩 가능) |
| Body 생성 전략 | FIXED / AI_GENERATE / AI_FILL |
| AI 힌트 | AI 컨텍스트 (AI 전략 사용 시) |
| Extract | 응답에서 추출할 변수 (JSONPath) |
| 조건 (선택) | 실행 조건. 불만족 시 스킵 |

#### 스크립트 타입

| 항목 | 설명 |
|------|------|
| 스텝명 | 식별용 |
| JavaScript 코드 | context 객체로 모든 변수 접근 가능 |
| 조건 (선택) | 실행 조건. 불만족 시 스킵 |

#### 레시피 타입 (서브레시피)

| 항목 | 설명 |
|------|------|
| 스텝명 | 식별용 |
| 대상 레시피 | 호출할 레시피 선택 |
| 조건 (선택) | 실행 조건. 불만족 시 스킵 |

- 순환 참조 방지: 레시피 저장 시 서브레시피 호출 순환 검증

#### 사용자 입력 타입

| 항목 | 설명 |
|------|------|
| 스텝명 | 식별용 |
| 입력 변수 목록 | 해당 스텝에서 사용자에게 물어볼 필드 정의 |
| 조건 (선택) | 실행 조건. 불만족 시 스킵 |

- 자동 실행 모드: 기본값이 있으면 물어보지 않고 사용
- 직접 입력 모드: 매번 액션 피커로 물어봄

### 6.4 조건 분기

각 스텝에 `condition` 필드를 붙여 조건부 실행/스킵 가능. 1차원 순차 구조 유지.

```json
{
  "name": "회원가입",
  "type": "recipe",
  "recipeId": 123,
  "condition": "{{Step0.statusCode}} === 401"
}
```

- 조건 만족 → 스텝 실행
- 조건 불만족 → 스킵하고 다음 스텝으로

### 6.5 실행 모드

레시피 실행 시 사용자에게 모드를 선택하게 함:

```
AI: "입사지원" 레시피를 찾았어요.
    로그인 → 이력서 확인 → 공고 선택 → 지원 순서로 진행됩니다.

    [자동 실행] [직접 입력하며 실행]
```

| 모드 | 동작 |
|------|------|
| **자동 실행** | 기본값 + AI 판단으로 진행. 판단 불가능한 것만 중간에 물어봄 |
| **직접 입력하며 실행** | 매 사용자 입력 스텝마다 액션 피커로 물어봄 |

사용자가 발화에서 이미 값을 지정한 경우("네이버 백엔드로 입사지원 해줘") 해당 값은 자동 반영.

### 6.6 실행 중 진행 상태 표시

```
📋 입사지원 실행 중

✅ 1. 로그인 확인
✅ 2. 이력서 확인
🔄 3. 공고 선택 (입력 대기 중)
⬜ 4. 입사지원 제출
⬜ 5. 결과 확인
```

- 완료 → ✅, 실행 중/입력 대기 → 🔄, 대기 → ⬜
- 사용자 입력 필요 시 해당 스텝에서 액션 피커 노출

### 6.7 스텝 간 데이터 전달

| 스코프 | 접근 방식 | 설명 |
|--------|-----------|------|
| 사용자 입력 | `{{userInput.변수명}}` | 액션 피커에서 받은 값 |
| 이전 스텝 추출값 | `{{변수명}}` | extract로 뽑은 값 |
| 이전 스텝 전체 응답 | `{{Step0}}`, `{{Step1}}` | 원시 응답 전체 |

### 6.8 스크립트에서의 변수 접근

```javascript
function execute(context) {
  const memberId = context.memberId;       // extract된 값
  const rawResponse = context.Step0;       // 0번 스텝 전체 응답
  const userInput = context.userInput;     // 사용자 입력값
  return { processedData: "..." };         // 다음 스텝에서 참조 가능
}
```

### 6.9 레시피 작성 화면 구성

세로 스크롤 form 구조. 사이드 패널 / 별도 페이지 양쪽에서 동일 컴포넌트 사용.

```
┌─────────────────────────────────────┐
│ 레시피 작성                     [저장] │
├─────────────────────────────────────┤
│ 레시피명: [________________]          │
│ 설명:    [________________]          │
│ 대상 서비스: [user-service ▾]        │
│ 태그:    [___] [___] [+추가]         │
│ 공개범위: (●공통 ○개인)               │
├─────────────────────────────────────┤
│ 사용자 입력 변수                      │
│ ┌─────────────────────────────────┐ │
│ │ productId: 상품 ID (text)  [🗑] │ │
│ │ quantity: 수량 (number)    [🗑] │ │
│ │ [+ 변수 추가]                    │ │
│ └─────────────────────────────────┘ │
├─────────────────────────────────────┤
│ 스텝                                │
│                                     │
│ ① 회원 목록 조회            [≡] [🗑] │
│   타입: API                         │
│   서브도메인: [user-service ▾]       │
│   API: [GET /api/v1/members ▾]      │
│   Extract: memberId = $.data[0].id  │
│                                     │
│ ② 주문 생성                 [≡] [🗑] │
│   타입: API                         │
│   서브도메인: [order-service ▾]      │
│   API: [POST /api/v1/orders ▾]      │
│   Body: { "memberId": "{{...}}" }   │
│   전략: FIXED                       │
│                                     │
│ ③ 결과 가공                 [≡] [🗑] │
│   타입: 스크립트                     │
│   코드: [에디터]                     │
│                                     │
│ [+ 스텝 추가]                        │
└─────────────────────────────────────┘
```

- [≡] = 드래그 핸들 (순서 변경)
- 각 스텝 접기/펼치기 가능
- 서브도메인/API는 스펙에서 가져온 목록으로 드롭다운 선택
- 변수 참조 시 자동완성 (이전 스텝 extract + userInput)

## 8. 스펙 등록 방식

외부 서버가 자신의 API 스펙을 ai-test-forge에 자동 등록하는 구조.

```
외부 서버 (client-spring 라이브러리 포함)
    │
    │ 1. 앱 기동 시 자동 등록 (OpenAPI JSON push)
    │ 2. 30초마다 heartbeat (변경 시에만 재전송)
    │
    ▼
ai-test-forge 서버 POST /api/v1/specs/register
    │
    ▼
DB 저장 → 레시피 작성 시 API 목록으로 활용
```

### 커스텀 어노테이션 (외부 서버에서 API별 제어)

| 어노테이션 | 역할 |
|-----------|------|
| `@TestForgeExclude` | API 목록에서 제외 |
| `@TestForgeBlock` | AI 호출 차단 |
| `@TestForgeConfirm` | 실행 전 확인 필요 |
| `@TestForgeHint` | AI에게 전달할 힌트 |
| `@TestForgeGroup` | 그룹 분류 |

### 인증 프로필

- 외부 서버 설정에서 loginPageUrl 정의
- 스펙 등록 시 함께 전송/저장
- 401/403 발생 시 해당 URL 제공

| 대화를 통한 레시피 생성 기능 | 추후 고도화 시 구현 |

| 레시피 공유/승인 프로세스 | 추후 고도화 시 구현 |
| 알림 기능 | 추후 고도화 시 구현. 현재는 채팅 목록 갱신 정도 |
| 기존 기능 유지 여부 (Auth, Workspace, Settings 등) | 기획 후 결정 |
