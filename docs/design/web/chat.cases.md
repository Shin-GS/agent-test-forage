## 레이아웃 구조

```
┌──────────┬────────────────────────┬──────────────────┐
│ 사이드바   │   대화 영역 (중앙)      │  사이드 패널 (우) │
│ (260px)  │   메시지 + 카드 + 입력  │  (기본 320px,    │
│          │   (중앙 clamp 컬럼)     │   우측 앵커 고정) │
└──────────┴────────────────────────┴──────────────────┘
```

- **좌측 사이드바**: ChatGPT식 통짜 스크롤 — 상단(로고+새 채팅)·하단(회원정보)만 고정, 그 사이(메뉴 nav · `─ 관리 ─` · 관리 메뉴 · `─ 대화 ─` · 대화 목록)가 하나로 스크롤. 항목은 좌측 정렬 축 통일, 새 채팅은 primary 강조.
- **중앙 대화 영역**: 메시지·입력창·액션 피커가 동일 **중앙 clamp 컬럼**(`clamp(680px, 70%, 920px)`) 축 공유. 사용자·AI 모두 좌측 정렬, 사용자 메시지는 옅은 배경 블록으로 구분(AI TEXT는 배경 없음, 카드/진행/결과는 자체 컨테이너).
- **우측 사이드 패널**: 항상 뷰포트 우측 앵커 고정, 폭은 CSS 변수(리사이즈는 폭만·가용폭 재-clamp·구분선 더블클릭 리셋). 반응형: <1200 오버레이 / <768 좌측 레일 / <480 단일 컬럼.

## 케이스 상세

### Case 1: 첫 접속 (빈 대화)

- 좌측 사이드바: 대화 목록 (없으면 빈 상태)
- 중앙: empty state
  - 앱 아이콘 + "무엇을 테스트할까요?"
  - 퀵 액션 버튼 2~3개 (자주 쓰는 레시피 바로가기)
- 하단: 채팅 input (placeholder: "테스트하고 싶은 내용을 입력하세요")
- 우측 패널: 레시피 목록 탭 활성

### Case 2: 대화 진행 중

- 사용자 메시지 + AI 응답 교차
- AI 응답에 tool-card 포함 (API 호출 결과)
- 메시지 호버 시 액션 버튼 (복사, 좋아요/싫어요)
- 헤더에 대화 제목 + 서비스 태그 + [변경] 버튼

### Case 3: 레시피 실행 중

- AI 메시지로 실행 시작 안내
- progress 컴포넌트: 스텝 진행 (완료/활성/대기)
- AI "..." 로딩 인디케이터 (타이핑 중 느낌)
- **입력 영역: 상태 배너로 잠금 이유 명시** ("⏳ 레시피 실행 중입니다" + [중지] 버튼)
  - 단순 disabled가 아니라, 채팅이 막힌 이유를 입력 지점에 표시 (session_status 반영)
  - AI 응답 생성 중이면 "⏳ 답변이 진행 중입니다" (중지 버튼 없음)
- **여러 탭 동기화**: 같은 대화방을 연 다른 탭도 SSE `session_status`로 동일하게 입력 잠금 상태를 표시

### Case 4: 액션 피커 표시

- 채팅 input 영역 위에 액션 피커 오버레이
- 예시 1: 버튼형 ("어떤 모드로 실행할까요?" + [자동 실행] [직접 입력])
- 예시 2: 다중 필드형 (라벨 + input + select + 확인/취소)
- 뒤쪽 채팅 input 비활성 (dim 처리)
- 취소 버튼 항상 존재

### Case 5: 결과 요약 + 카드

- AI 응답으로 실행 결과 요약 텍스트
- 결과 카드: 레시피명 + 실행 시각 + 상태 뱃지 + [결과 보기] 버튼
- [결과 보기] 클릭 시 사이드 패널에 상세 결과 표시 (이 HTML에서는 시각적 표현만)
- 체크리스트 형태: ✓ 성공 / ✕ 실패 스텝 요약

### Case 6: 에러 상태

- 에러 카드: "API 호출 실패" + 에러 코드/메시지
- 재시도 카드: [다시 시도] 버튼
- alert 스타일: error 배경 + 메시지

### Case 11: 플랜 제안 (읽기 전용 — 1단계)

- 헤더 "📋 실행 계획 (N단계)" (N=레시피 수)
- 💡 rationale 한 줄 (AI 근거) — 사용자가 조합 타당성을 판단하는 근거
- 레시피 목록 (읽기 전용): 순서 배지 + 이름 + [서비스] 뱃지 + 값 미리보기 한 줄
  - 값 미리보기: 레시피 기본값(📌)만 확정 표시. 발화값(🗣️) 포함 나머지는 **"실행 중 결정"**(흐림 처리) — 발화값의 레시피별 분배는 1단계 범위 밖
  - **🔗 이전 결과 예측 표시 금지** (실행 전에는 확정 불가)
- [취소] [자동 실행 ▶]
- 편집 UI 없음(체크박스/드래그/값편집/추가·제거 = 2단계 백로그)

### Case 12: 플랜 실행 중 (PROGRESS)

- 헤더 "📋 플랜 실행 중 (k/N 레시피)"
- 완료 레시피: 접힘(✅ + 결과 한 줄) / 현재 레시피만 스텝 펼침(✅완료 · 🔄진행 · ⬜대기 · ⏭️스킵 · ❌실패) / 대기 레시피: ⬜
- 레시피 전이 announce: `role="status" aria-live="polite"`(sr-only)
  - **FE 구현 필수**: announce 노드는 초기 렌더 시 빈 상태로 두고, 레시피 전이 시점에 텍스트를 주입해야 스크린리더가 읽는다 (정적 렌더 상태로는 announce가 발생하지 않음)
- 입력 영역: 잠금 + [중지] 버튼(`btn--secondary` — 되돌릴 수 없음 경고는 Case 20 확인 모달이 담당) → 클릭 시 Case 20 확인 모달

### Case 13: 중단 상태

- ⏹️ 중단 지점 + 완료/미실행 레시피 상태
- "완료된 N개 결과는 보존됩니다 (되돌릴 수 없음)"
- 버튼 [처음부터 다시 실행]만 — **1단계는 [이어서 실행](PARTIAL 재개) 없음**

### Case 18: 레시피 사이 입력 (실행 중 pre-run 액션 피커)

- 현재 RUNNING 레시피의 미충족 입력 변수만 수집 (기존 액션 피커 재사용)
- 값 출처 뱃지: 🔗 이전 결과(**실행 중에만 노출 OK**) / 🗣️ 발화 / 📌 기본값 / ✏️ 직접 입력
- [취소] [계속 ▶]
- 진행 카드: 완료 레시피 접힘, 현재 레시피 "입력 대기 중"

### Case 19: 플랜 실패 (1단계)

- ❌ 실패 레시피 + 사유(스텝/코드), 완료(✅)/미실행(⬜) 레시피 상태
- 안내 "레시피 N에서 실패했어요. 레시피 1~(N-1)은 완료됐습니다 (되돌릴 수 없음)"
- error alert + 버튼 **[플랜 중단]만** (이어서 실행 없음)
- 사이드 패널 히스토리: "부분 실패"(PARTIAL) 뱃지

### Case 20: 사용자 중단 확인 모달

- 실행 중 [중지] 클릭 시 노출 (`role="dialog" aria-modal="true"`)
- "완료된 N개 레시피는 되돌릴 수 없습니다. 중단하시겠습니까?" + 생성 데이터 유지 안내
- [계속 실행] / [중단](danger)

### Case 21: 플랜 결과 (RESULT)

- "📋 플랜 완료 (N/N)" + 상태 + 소요 시간 (**추정 시간 표시 금지**)
- 레시피별 결과 한 줄 (✓ 이름 — 결과)
- [▸ 상세 보기](비활성 — 사이드 패널 결과 상세는 후속) / [다시 실행]

### Case 16: 정보 조회 중 (INVESTIGATE_PROGRESS)

- 헤더 "🔍 정보 조회 중"
- 소스별 조회 단계 리스트: 상태 아이콘 텍스트 병기 (✅ 완료 / 🔄 진행 중 / ⬜ 대기 / ⏭️ 스킵)
  - 예: "✅ API 스펙 확인 — 회원가입 스키마", "🔄 API 스펙 조회 중 — '약관 동의 필드'"
  - **1단계는 `api_spec` 커넥터만 노출** (confluence는 [2단계](../../specs/chat/scenarios/investigation.md#confluence-커넥터-조회-정의-2단계))
  - ⏭️ 스킵: 미지원 source 또는 중복 `(source, query)` 캐시 재사용 — 카운터 소비
- 단계 전이 announce: `role="status" aria-live="polite"`(sr-only)
  - **FE 구현 필수**: aria-live announce 노드는 초기 빈 상태로 렌더하고 조회 단계 전이 시점에 텍스트를 주입한다 (정적 렌더로는 announce 미발생, Case 12 패턴 동일). **디자인 HTML의 예시 텍스트는 데모용이며 정적 렌더 금지** — 실제 구현/디자인 노드 모두 빈 상태로 시작
- `message_update`로 같은 INVESTIGATE_PROGRESS 메시지 갱신 (새 메시지 안 쌓음)
- 입력 영역: 조회 중 잠금 (session_status 반영)
- **종료 상태 확정** (running 잔존 금지 — finally 확정):
  - 실패/타임아웃은 **별도 케이스 없이** 진행 블록을 종료 상태로 확정 + 폴백 안내 (Case 6 패턴 재사용)
  - 타임아웃 → 헤더 `--timeout` + "조회 시간이 초과되었습니다"
  - 못 찾음/실패 → 헤더 `--failed` + "정보를 찾지 못했습니다" (AI 비의존 고정 안내, 억지 답변 없음)
  - **실렌더 확인**: chat.html **Case 16b(조회 실패/타임아웃)**에서 타임아웃/실패 확정 상태를 실제 마크업으로 렌더 (running 잔존 없음 눈으로 검수). 읽기 전용+자동 종료이므로 중단 버튼 없음

### Case 17: 참고 자료 (조회 완료 답변 + references)

- AI 답변 본문(Markdown): **출처 근거 인용 포함** (예: "POST /api/v1/users 요청 스키마의 `agreementYn` 필드가 required")
- 하단 "참고한 자료:" + references 칩(button) 리스트
  - **1단계는 `api_spec` 소스만** → 칩 [📋 method + path ▸], **클릭 시 그 자리에서 엔드포인트 상세를 인라인 아코디언으로 펼침** (`aria-expanded` 토글, 각 칩 독립 — 여러 개 동시 펼침 가능). 확장 인디케이터 ▸ 접힘 / ▾ 펼침
  - 펼친 상세: 서비스명 + method/path + summary + description. 펼침 시점에 DEPRECATED/INACTIVE면 `badge--warning`("지원 종료") 표시(상세는 유지). 하단 "전체 스펙 보기 →" 링크는 **관리자만 렌더**(일반 사용자 미렌더)
  - `url`(`/specs/{apiSpecId}/endpoints/{endpointId}`) 파싱 실패 시 비인터랙션 정적 칩으로 폴백. 로딩/실패/엔드포인트 없음 상태 안내는 [investigation.md](../../specs/chat/scenarios/investigation.md#인라인-확장-동작-1단계-api_spec-칩)
  - 📄 Confluence 칩은 [2단계](../../specs/chat/scenarios/investigation.md#confluence-커넥터-조회-정의-2단계) — 1단계 미노출
- 조회한 소스가 없으면 참고 자료 섹션 미표시 (순수 TEXT)
- references payload는 답변 TEXT 메시지에 저장 → 새로고침 복원 ([messaging.md references](../../specs/common/messaging.md#references-정보-조회-참고-자료))

| 구간 | 사이드바 | 중앙 영역 | 패널 |
|------|---------|----------|------|
| Desktop (1200px+) | 260px (펼침) | flex + 중앙 clamp 컬럼 | 우측 앵커 고정 (기본 320px) |
| 좁은 데스크톱 (768~1199px) | 260px (펼침) | flex | 오버레이 (가용폭 부족 시) |
| Tablet (768px 이하) | 60px (레일, 아이콘만) | flex | 오버레이/닫힘 |
| Mobile (<480px) | 레일/드로어 | 단일 컬럼 | 오버레이 |

> 반응형 기준은 창 폭이 아니라 **가용폭**(창 폭 − 사이드바 − 중앙 최소폭)이다. 가용폭이 부족하면 패널을 오버레이로 전환해 중앙 채팅 최소폭(`--chat-min-width`)을 우선 보장한다.

## 패널 인터랙션

- 좌측 사이드바: 토글 버튼으로 접기/펼치기 (접힘 시 60px 레일, 아이콘만 / 대화 목록 숨김)
  - 통짜 스크롤: 상단(로고+새 채팅)·하단(회원정보)만 고정, 그 사이(메뉴·`─관리─`·관리 메뉴·`─대화─`·대화 목록)가 하나로 스크롤
  - 펼침 시 active 대화가 보이도록 `scrollIntoView` (단, 접힘 상태에서는 예외 — 대화 목록 자체가 숨김)
- 우측 패널: 항상 뷰포트 우측 앵커 고정, 토글 버튼으로 열기/닫기 (닫힘 시 완전 숨김)
- 리사이즈: 경계선 드래그로 너비 조절
  - 사이드바: 200~400px
  - 패널: CSS 변수 폭(`clamp` 240px ~ 640px). 드래그는 폭만 변경, 창을 좁히면 가용폭 기준으로 재-clamp
  - 구분선 **더블클릭 시 기본 폭으로 리셋**
- 드래그 중 경계선 accent-subtle 하이라이트
- 너비/상태: localStorage에 저장 → 새로고침 시 복원 (패널 폭 키: `testforge.ui.rightPanel.width`)

## 사이드바 상태 뱃지

- 🟡 입력 대기 (레시피가 사용자 입력 기다리는 중)
- 🔄 처리 중 (AI 응답/실행 중)
- 🔵 안 읽음 (새 메시지)
- (없음) 유휴

## 대화 제목 / 서비스 태그 위치 (chat-header 폐지)

채팅 영역 상단의 별도 헤더 바(chat-header)는 **폐지**했다. 대화 제목·서비스 태그·[변경]은 우측 사이드 패널의 서비스 블록(🏷️)에서 다룬다. 중앙 대화 영역은 헤더 없이 메시지 컬럼과 입력창만 둔다.

- 서비스 태그/변경: 사이드 패널 상단 서비스 블록 (`PanelServiceBlock`, 🏷️ 서비스명 + [변경]) — 상세는 [panel.cases.md](./panel.cases.md)
- 대화 제목: 좌측 사이드바 대화 목록 항목에 표기

## 접근성

- 메시지 영역 aria-live="polite" (새 메시지 알림)
- 액션 피커 포커스 트랩 (열리면 첫 필드로 포커스)
- 사이드바 항목 role="listitem"
- 키보드: Enter로 메시지 전송, Shift+Enter로 줄바꿈
