# 사이드 패널 케이스

## 참조 기획

- [패널 구조](../../specs/panel/overview.md)
- [작업 히스토리](../../specs/panel/history.md)

## 개요

채팅 우측에 항상 열려있는 보조 패널. 레시피 탐색 + 히스토리 확인 + 결과 상세.
스택 네비게이션 (상세 → 뒤로가기 → 목록).

## 케이스 목록

| # | 케이스 | 설명 |
|---|--------|------|
| 1 | 레시피 목록 (기본) | 탭 필터 + 레시피 카드 목록 (접힘 상태) |
| 2 | 레시피 카드 펼침 (인라인 상세) | ▾ 클릭 → 카드 안에서 범위/서비스/태그 + 스텝 흐름 + 입력 변수 (별도 뷰 아님) |
| 2a | 카드 펼침 — 스텝 지연 로딩 | 펼칠 때 상세 조회 중 |

## 케이스 상세

### Case 1: 레시피 목록 (기본, 카드 접힘)

- 상단(대상 서비스 블록 아래): 탭 [홈] [레시피] [히스토리] — 레시피 활성
- 서비스 선택 드롭다운(탐색 전용) + 검색 입력 필드
- 필터: [전체] [내 레시피] [공통] (즐겨찾기 필터는 2차 — 현재 없음)
- 레시피 카드(접힘):
  - 1행: 레시피명 + **⚠️**(INVALID일 때만, Case 2c) + [▾ 펼치기] + [▶ 실행]
  - 2행: 설명 1줄 (작은 폰트, 말줄임)
  - 3행: 사용정보 (🕒 최근 사용 상대시각 · N회)
- 하단 [+ 레시피 만들기] 버튼 **없음**(관리는 별도 /recipes 페이지). 레시피 0개면 Case 5 빈 상태.

### Case 2: 레시피 카드 펼침 (인라인 상세)

> 이 카드는 **레시피 탭과 홈 탭("자주 쓴 레시피")이 동일한 공통 컴포넌트**를 쓴다. 아래 동작은 두 위치에서 똑같이 적용된다.

카드 [▾]를 누르면 **그 자리에서 인라인 상세를 펼친다**(별도 상세 뷰로 이동하지 않음). ▾ → ▴ 토글. 여러 카드 동시 펼침 가능.

- **즉시 표시(추가 조회 없음)** — 구분선 아래:
  - 공개 범위 배지: 🌐 공통 / 🔒 개인 (`RecipeSummary.visibility`)
  - 서비스명 — 목록 응답엔 없으므로 **레시피 탭이 이미 로드한 서비스 목록(`GET /specs`)을 `apiSpecId`로 매핑**(접힘 카드 배지와 동일 소스). 매핑 실패 시 생략.
  - 태그 칩 (`#주문` `#결제` …, `RecipeSummary.tags`). 태그 없으면 생략.
- **지연 조회(펼칠 때 `recipesApi.detail` 1회 + 캐시)**:
  - 스텝 흐름: `번호. 스텝명 [타입 배지]` 목록. 스텝명 폴백 = (API 스텝) label → name / (스크립트·서브레시피) name / 최종 "스텝 N". 타입 배지 = API/스크립트/서브레시피/사용자입력.
  - 입력 변수: "입력 변수: {label 우선, 비면 key}, …". 많으면 "… 외 N개".
- **정상 응답이지만 스텝 0개**: "등록된 스텝이 없어요." (실패가 아님 — Case 2b와 구분)
- 처리 중 락: 대화방이 처리 중이어도 ▾ 펼침/조회는 허용([▶]만 비활성).
- 목록 재조회(검색어/필터/서비스 변경) 시 펼침 상태는 초기화(접힘), detail 캐시는 유지.
- 접근성: [▾]에 `aria-expanded`/`aria-controls`. 펼침 영역은 펼쳤을 때만 렌더.

### Case 2a: 카드 펼침 — 스텝 지연 로딩

- 즉시 표시(범위/서비스/태그)는 먼저 보이고, 스텝/변수 영역만:
  - `⟳ 스텝 정보를 불러오는 중…` (스피너, `role="status" aria-live="polite"`)
- 두 번째 펼침부터는 캐시로 즉시 표시(로딩 생략).

### Case 2b: 카드 펼침 — 상세 조회 실패

- 스텝/변수 영역에 인라인 에러: `⚠️ 스텝 정보를 불러오지 못했어요.` (`role="alert"`)
- 카드 레이아웃은 깨지지 않는다(즉시 표시 영역은 정상 유지).
- (빈 스텝(스텝 0개)은 실패가 아니라 정상 응답 — Case 2 본문 "등록된 스텝이 없어요." 참조)

### Case 2c: 카드 — 유효성 경고 (INVALID)

- 레시피 `validationStatus`가 INVALID면 이름 옆에 ⚠️.
- hover/focus 시 툴팁: "스펙 변경으로 필수 필드가 무효화됨" (레시피 관리 목록과 동일 표기, AppTooltip).
- 실행을 차단하지 않는다 — 실행 시 Case 6 모달에서 경고 문구로 안내.

### Case 3: 히스토리 목록

- 상단: 탭 [레시피] [히스토리] — 히스토리 활성
- 실행 기록 목록:
  - 레시피명 + 실행 시각
  - 상태 뱃지 (성공/부분실패/실패)
  - 간략 요약 (N/M 스텝 성공)
- 항목 클릭 → 실행 결과 상세

### Case 4: 실행 결과 상세

- 상단: [← 뒤로] + "실행 결과"
- 기본 정보: 레시피명, 실행 시각, 소요 시간
- 스텝별 결과 목록:
  - 스텝 표시명(폴백 체인) + 상태 (✓/✕)
  - 스텝 표시명 폴백: (1) 스텝 label → (2) 엔드포인트 summary → (3) method + path
  - 결과키 표시명: label 있으면 사람말(예: "회원 ID"), 없으면 원본 key(예: `statusCode`)로 폴백
  - 중첩/배열 key는 경로 그대로 표기, 값이 null이면 "값 없음"
  - 펼치면 입출력 JSON (코드 블록)
- 상세는 이원화 유지: 사람말 표시명 + 기술 원문(method + path, 원본 key) 병기 허용
- 실패 스텝: 기술 원문(에러 코드/원본 응답) 노출 허용
- 참조 기획: [response-guide.md 표시명 폴백 체인](../../specs/common/response-guide.md#표시명label-폴백-체인)

### Case 5: 빈 상태

- 레시피 없음: "아직 레시피가 없어요" + [레시피 만들기]
- 히스토리 없음: "아직 실행한 레시피가 없어요"
- 검색 결과 없음: "'{검색어}'에 해당하는 레시피가 없어요"

### Case 6: 실행 확인 모달 (레시피 ▶)

패널의 홈(레시피 목록/최근 실행) 또는 레시피 탭에서 [▶] 바로 실행을 누르면, 즉시 실행/발화 전송하지 않고 **확인 모달**을 먼저 띄운다 (오클릭·탐색 중 실행 방어).

- 트리거: 홈/레시피 탭의 레시피 카드 [▶] (접힘/펼침 무관 — 별도 상세 뷰는 없음)
- 모달 구성 (기존 `ConfirmModal` 재사용):
  - 제목: **"실행할까요?"**
  - 본문: 레시피명 + 서비스 배지 + 설명 1줄
  - **INVALID 경고**: 대상 레시피가 INVALID면 본문에 "스펙 변경으로 유효하지 않을 수 있어요. 실행은 되지만 일부 스텝이 실패할 수 있어요." 추가 (실행 차단 아님)
  - 버튼: [취소] / [실행] (2버튼, 중립 톤 — 파괴적 아님)
  - 초기 포커스: **[취소]**
- 동작:
  - [취소] / ESC / 배경 클릭 → 아무 동작 없이 닫힘 (발화 전송 안 됨)
  - [실행] → 기존 실행 flow 진입 (발화 "{레시피명} 실행하기" + 지목 레시피(targetRecipeId) 전송, `handleRunRecipe`)
- 대화방이 처리 중이면 [▶]가 비활성(`aria-disabled`)이라 모달이 뜨지 않는다
- 서비스 불일치(대화방 서비스 ≠ 레시피 서비스)는 이 모달이 아니라 **실행 후 별도 서비스 변경 확인 단계**에서 다룬다 (거부 시 no_match/clarify, 발화는 유지)
- 층위 구분: 이 패널 모달 = "발화를 보낼지" 확인 / 채팅의 실행 카드 = "어떤 방식으로 실행할지"(자동/직접) 선택. 이중 확인이 아니다. 상세는 [panel/overview.md](../../specs/panel/overview.md), [card-ui.md](../../specs/chat/card-ui.md)

### Case 7: 재실행 확인 모달 (히스토리 ▶)

히스토리 목록/결과 상세에서 [▶] 재실행을 누를 때의 확인 모달. Case 6과 동일 구조이나 문구만 다르다.

- 제목: **"다시 실행할까요?"**
- 재실행 = 이어서 실행/재개가 아니라 **신규 실행**임을 명확히 (본문 또는 보조 문구)
- 나머지(본문 구성·버튼·초기 포커스 [취소]·ESC/배경 취소·처리 중 비활성)는 Case 6과 동일

## 반응형

| 구간 | 패널 |
|------|------|
| Desktop (1200px+) | 우측 앵커 고정, CSS 변수 폭(기본 320px, `clamp` 240~640px) |
| 좁은 데스크톱 (768~1199px) | 가용폭 부족 시 오버레이 (중앙 채팅 최소폭 우선) |
| Tablet 이하 (<768px) | 오버레이/닫힘 (버튼으로 열기) |

> 폭 기준은 창 폭이 아니라 **가용폭**(창 폭 − 사이드바 − 중앙 최소폭). 패널 폭 리사이즈는 폭만 변경하고, 창을 좁히면 재-clamp된다. 구분선 더블클릭 시 기본 폭으로 리셋. 상세는 [chat.cases.md 패널 인터랙션](./chat.cases.md#패널-인터랙션).

## 접근성

- 스택 네비게이션: 뒤로가기 버튼에 aria-label
- 레시피 목록: role="list" + role="listitem"
- 실행 버튼: aria-disabled when 대화방 처리 중. **[▶]에 `aria-label="{레시피명} 실행"`**(이모지만으로 접근 이름이 되지 않게)
- 카드 펼치기: **[▾ 펼치기] 토글에 `aria-expanded` + `aria-controls`**(펼침 영역 id 연결). 펼침 콘텐츠는 펼쳤을 때만 DOM에 렌더
- 지연 로딩 상태: 로딩은 `role="status" aria-live="polite"`, 실패는 `role="alert"`
- 유효성 경고 ⚠️: 아이콘만으로 정보를 전달하지 않게 툴팁/aria로 사유 노출(AppTooltip)
- 실행/재실행 확인 모달 (Case 6/7): `role="dialog"` + `aria-modal`, focus trap, 초기 포커스 [취소], ESC/배경 클릭으로 닫힘. 이 동작은 **`ConfirmModal`(Base UI Dialog) 래퍼가 담당**하며 FE가 직접 구현하지 않는다([ui-patterns.md](../../specs/common/ui-patterns.md#오버레이-구현-규칙-base-ui-래퍼로만)). 대상 서비스 선택 드롭다운은 `AppMenu`(Base UI Menu) 사용.
