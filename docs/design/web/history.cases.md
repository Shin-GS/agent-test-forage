# 전체 히스토리 페이지 케이스

## 참조 기획

- [전체 히스토리 페이지](../../specs/pages/history-full.md)

## URL

- `/history` — 히스토리 목록(목록형). 테이블 뷰.
- `/history/:executionId` — 실행 결과 상세(상세/편집형 페이지). 모달 아님.

## 레이아웃

- 목록: 별도 페이지. 전체 화면 테이블 뷰. Tablet 이하(<1024px)에서는 카드 폴백.
- 상세: 별도 페이지(`PageShell` + `PageActionBar`). 스펙 상세(`/admin/specs/:id`)와 동일 골격. 좁은 폭에서는 요약/결과값/스텝을 세로 스택.

## 케이스 목록

| # | 케이스 | 설명 |
|---|--------|------|
| 1 | 목록 (기본) | 실행 히스토리 테이블 + 필터 바 + 결과 카운트("총 N건") |
| 2 | 상세 — 성공 | 행 클릭 → 페이지 이동(`/history/:executionId`). 액션 바 + 요약 헤더 + 결과값 + 스텝(펼침 시 JSON, 복사) |
| 3 | 상세 — 실패 | 실패 요약 배너([실패 지점으로 이동]) + 실패 스텝 강조 |
| 4 | 상세 — 로딩 | 딥링크/새로고침 직접 진입 시 스켈레톤/스피너 |
| 5 | 상세 — 404/권한없음 | 타인·삭제 실행 접근 → 빈 상태 안내 + [목록으로] |
| 6 | 상세 — 플랜(다중) | 레시피별 세로 나열(레시피명 구분 + 각 결과값/스텝) |
| 7 | 목록 빈 상태 | 실행 이력 없음(🕘 + 채팅 유도) |
| 8 | 목록 필터 결과 없음 | 조건에 맞는 이력 없음 + [필터 초기화] |
| 9 | 반응형 카드 폴백 | Tablet 이하(<1024px) — 목록 행을 세로 카드로 전환. 카드 클릭도 상세 페이지로 이동 |

## 확정 UX

### 목록 컬럼 (최신순 고정, `startedAt DESC`)

`실행 시각 | 레시피명(+결과 요약 1줄) | 서비스 | 상태 | 소요시간`

- **결과 카운트**: 필터 바 하단에 "총 N건" 표기.
- **행 색 강조는 토큰 기반, 배지-행 색 언어 일치**(하드코딩 금지):
  - 실패(❌)=error 계열(`--color-error-subtle`)
  - 중지(⏹️)=배지가 neutral이므로 행도 **중립 배경**(`--color-bg-hover`) — warning으로 쓰지 않음(배지-행 색 언어 일치).
- **커서 무한 스크롤**: 목록은 `startedAt DESC` 커서 기반 무한 스크롤이 데이터 계약. 테이블/카드 하단 sentinel 도달 시 다음 커서를 요청하고, 로딩 중에는 하단에 로딩 표시(스피너 컴포넌트 재사용), 마지막 페이지 도달 시 종료 문구로 전환.

### 필터 바 (레시피 목록의 FilterDropdown 패턴과 일관)

모든 필터는 **다중 선택 + "빈 선택 = 전체"**. 필터 변경 시 커서 리셋 후 처음부터 재조회.

| 항목 | 방식 |
|------|------|
| 검색 | 레시피명 텍스트(디바운스) |
| 서비스 | 다중 선택 드롭다운(`apiSpecId`) |
| 상태 | 다중 선택 드롭다운 — ✅성공(SUCCESS) / ❌실패(FAILED) / ⏹️중지(STOPPED) / ⏸️취소(CANCELLED) |
| 기간 | 날짜 범위(from~to) — date input 2개 |

- 활성 필터 요약 줄 + 필터 칩(제거 가능) + [필터 초기화].
- 진행중(RUNNING)·부분성공(PARTIAL)은 상태 필터 옵션에서 제외(완료 이력 조회용).

### 상태 아이콘

✅ 성공 / ❌ 실패 / ⏹️ 중지 / ⏸️ 취소 (PARTIAL 행은 목록엔 노출되나 필터 옵션엔 없음)

### 상세 페이지 (ExecutionDetailView 재사용, `/history/:executionId`)

모달이 아니라 별도 페이지다(전환 근거·규칙: [ui-patterns.md](../../specs/common/ui-patterns.md), [history-full.md](../../specs/pages/history-full.md#실행-결과-상세-별도-페이지)). 스펙 상세와 동일하게 `PageShell` + `PageActionBar` 골격을 쓴다.

> **하나의 화면 + 조건부 요소**: 성공/실패, 단일/플랜은 별도 화면이 아니라 같은 화면의 데이터 변형이다. `recipes[]`를 순회 렌더하는 단일 컴포넌트로 구현하며, 단일은 "N=1 플랜"으로 취급한다. 아래 "성공/실패/플랜/로딩/404"는 같은 화면의 상태 예시일 뿐이다.

**상단 액션 바(`PageActionBar`)**

- `[← 목록으로]` — 직전 목록 URL(필터 유지)로 복귀. 딥링크 직접 진입 시 `/history` 폴백. 브라우저 뒤로가기도 동일.
- 제목: 실행 제목 + 상태 아이콘 / meta: 상태 배지(성공/실패/중지/취소/부분성공)
- 우측 액션: **없음**. 원본 레시피 링크는 액션 바가 아니라 **레시피 블록 헤더**로 이동(실행이 레시피 여러 개일 수 있어 "원본" 하나로 특정 불가).

**요약 헤더**

- 첫 지표는 단일/플랜 분기: **단일 = 서비스명**, **플랜 = 유형(N개 레시피)**. (`API_SPEC_ID`는 첫 레시피 것 하나뿐이라 플랜은 대표 서비스 대신 유형+개수 표기, 서비스는 레시피 블록에서 파악)
- 공통: 실행 모드(자동/직접) · 스텝 성공률(N/M) · 소요시간
- 실행 시각: **절대시각 기본 + 상대시각 병기**(예: `2026-09-15 14:32:07 (3시간 전)`)

**실패 스텝 강조/점프** (실패·부분성공 시)

- 요약 아래 실패 요약 배너: "{N}번 스텝 "{스텝명}"에서 실패"(가능하면 상태코드). 여러 건이면 첫 실패 기준. 플랜이면 레시피명 병기.
- [실패 지점으로 이동] → 해당 스텝으로 스크롤. 실패 스텝 행은 error 계열 토큰으로 강조.

**레시피 블록 (레시피별 헤더 + 원본 링크)**

- 본문은 `recipes[]`를 순회해 **레시피 블록**을 세로로 나열(단일=1개, 플랜=N개, 동일 규칙).
- 각 블록 헤더: 레시피명 + **버전 안내** + **`[🔗 원본 레시피]`**. 판정은 레시피별 `recipeDeleted`/`recipeCurrentVersion`/`recipeVersionNo`로:
  - 삭제/부재 → 링크 비활성("원본 삭제됨")
  - 버전 동일 → 링크 활성, 버전 안내 생략
  - 버전 상이 → 링크 활성(최신 원본), "v{실행버전} 기준 · 원본 현재 v{현재버전}" 배지/툴팁
- 단일 실행도 레시피 블록 헤더를 동일하게 표시(특수 분기 없음).

**본문(결과값 + 스텝)** — 각 레시피 블록 안

- 스텝별: 상태 아이콘 + 요약 1줄. 펼침 시 원본 응답 JSON(`RESPONSE_JSON`) + 사용자 입력값(`USER_INPUT_JSON`).
- **복사**: 결과값·스텝 JSON에 복사 버튼(채팅 답변 복사와 동일한 상호작용 — 복사 + "복사되었습니다" 토스트 + 잠깐 ✓). 공통 컴포넌트로 통일.
- 넓은 폭에서 JSON 블록을 크게(1단; 좌우 2단은 백로그).

**상태별**

- 로딩: 데이터 도착 전 스켈레톤/스피너(딥링크/새로고침 직접 진입 대비).
- 404/삭제/권한없음: 전용 빈 상태 안내 + [목록으로](스펙 상세와 동일 패턴, 토스트 아님).

**공통**

- 데이터: `GET /api/v1/executions/{id}` — 본인 소유 검증, 타인 접근 404.
- 실행 시점 스냅샷 기준 렌더링.

## 접근성

- 테이블에 적절한 `thead`/`tbody`, `scope="col"` 헤더
- 상세 **페이지**: `PageShell`이 sr-only `<h1>`("실행 히스토리 — {실행 제목}") + `document.title`을 처리. 상단 액션 바는 sticky.
  - 뒤로가기 버튼은 `aria-label` 명시. 브라우저 뒤로가기와 동작 일치.
  - 스텝 펼침은 `<details>`/`<summary>`로 키보드 접근. 복사 버튼은 `aria-label` + 완료 시 `aria-live` 안내.
  - [실패 지점으로 이동]은 해당 스텝으로 스크롤 후 포커스 이동(FE 구현 범위).
  - 404/권한없음 빈 상태는 `role="alert"` 또는 안내 텍스트 + [목록으로] 버튼.
- 필터 변경 시 결과 개수를 `aria-live="polite"`로 알림
- 무한 스크롤 하단 로딩 표시는 `role="status"` + `aria-live="polite"`
- 날짜 input은 `<label for>`로 연결
- 필터 드롭다운: `aria-haspopup`/`aria-expanded` 동기화, ESC/바깥 클릭 닫기, roving 포커스, 닫으면 트리거 복귀. 이 동작은 **`AppMenu`(Base UI Menu) 래퍼가 담당**하며 FE가 직접 구현하지 않는다([ui-patterns.md](../../specs/common/ui-patterns.md#오버레이-구현-규칙-base-ui-래퍼로만)). 다중 선택은 `Menu.CheckboxItem`(선택 중 메뉴 유지).
- **반응형 카드 폴백(`exec-cards`)**: 데스크톱 테이블과 동일 데이터의 반응형 대체 표현이라 기본 `aria-hidden="true"`. 단, <1024px 미디어쿼리로 카드가 노출될 때는 `aria-hidden="false"`로 토글해야 스크린리더에서 낭독됨(FE 구현 범위).

## 백로그 (구현 안 함, 기록만)

- [다시 실행] 버튼, 날짜 그룹 헤더, CSV/JSON 내보내기, 통계 요약 바, 멀티 타임존 대응
- 상세: 이전/다음 실행 이동(갤러리식), 스텝 좌우 2단 레이아웃, 플랜 레시피별 탭/앵커 목차
