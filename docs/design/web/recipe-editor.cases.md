## 레이아웃

별도 페이지 (채팅 레이아웃 벗어남). 전체 화면 사용.
상단은 제목 전용 헤더가 아니라, 목록형=툴바 / 편집형=액션 바로 구성한다([page-layout.md](../../specs/common/page-layout.md)).

```
┌──────────────────────────────────────────────────────────┐
│ [← 목록으로]  레시피명(액션 바)          [버전 기록] [저장] │  ← 편집형 액션 바
├──────────────────────────────────────────────────────────┤
│ ① 메타 정보                                              │
│ ② 사용자 입력 변수                                        │
│ ③ 스텝 (2단: 설정 + 데이터 탐색기)                        │
│ ④ 결과 정의                                              │
│ ⑤ 결과 메시지 템플릿                                      │
└──────────────────────────────────────────────────────────┘
```

## 스텝 타입 (확정)

프로토타입 스텝 타입은 **API / 스크립트 / 서브레시피 3종**이다.
"사용자 입력"은 별도 스텝 타입이 아니라 레시피 메타의 **② 사용자 입력 변수**로 대체한다.
(실행 중 입력을 받는 별도 스텝 타입은 추후 확장 — 이번 프로토타입 범위 아님)

## 케이스 상세

### Case 1: 레시피 목록

- 상단(목록형 툴바): 제목 전용 헤더 없이 검색/필터 + 우측 끝 [+ 레시피 만들기] 버튼([page-layout.md](../../specs/common/page-layout.md)). 제목은 `sr-only` `<h1>`로만 남긴다.
- 필터: 검색 + 서비스 드롭다운 + 공개범위(전체/공통/개인)
- 테이블: 레시피명, 서비스, 공개범위, 태그, 최종 수정일, 액션(편집/복제/삭제)
- 행 클릭 → 편집 페이지

### Case 2: 새 레시피 생성

- 상단(상세/편집형 액션 바): [← 목록으로] + "새 레시피" + 우측 [저장]([page-layout.md](../../specs/common/page-layout.md)). 제목 전용 헤더 대신 액션 바를 쓰며, 제목은 `sr-only` `<h1>`로도 남긴다.
- ① 메타: 레시피명, 설명, 대상 서비스(드롭다운), 태그(칩 입력), 공개범위(라디오)
- ② 변수: 빈 테이블 + [+ 변수 추가]
- ③ 스텝: 빈 상태 + [+ 스텝 추가] 버튼 (타입 선택 드롭다운)
- ④ 결과 정의: 빈 테이블 (변수명 | 표시명(선택) | 소스)
- ⑤ 결과 메시지: textarea + 라벨 옆 도움말 툴팁(ⓘ)

### Case 3: 스텝 편집 (API 타입)

- 2단 레이아웃:
  - 좌측: 스텝 설정 (대상 서비스 선택 → API 선택 → 요청 필드/헤더 자동 나열 → 값 소스 매핑)
  - 우측: 데이터 탐색기 (이전 스텝 변수 + 사용자 입력 + 현재 API 스키마 — 요청 필드/요청 헤더)
- 값 소스/매핑 값 선택 컨트롤(`.mapping-source`)은 FE 구현 시 정적 span이 아니라 실제 `<select>` 또는 Base UI Combobox(`role`/`aria-label` 포함)로 구현한다. 목업의 span은 시각 표현용.
- 스텝 표시명(선택) 입력: 비우면 폴백 (엔드포인트 summary → method + path). placeholder로 자동 안내
- Extract 섹션: 응답에서 변수 추출 정의
- 조건(선택): 조건 빌더
- ④ 결과 정의: 변수명 | 표시명(선택) | 소스. 표시명 있으면 사람말, 비우면 원본 key로 폴백 (예시로 label 있음/없음 행 모두 노출)

#### 스텝 대상 서비스 선택 (멀티 서비스 — 확정)

한 레시피의 스텝들이 서로 다른 서비스를 호출할 수 있다(멀티 서비스). 각 API 스텝은 자기 서비스(`apiSpecId`)를 스텝 상단에서 선택하고, 그 서비스에 속한 endpoint(`endpointId`)를 API 드롭다운에서 고른다. 참조: [structure.md 멀티 서비스 실행 규칙](../../specs/recipe/structure.md#멀티-서비스-실행-규칙-확정), [structure.md 스텝 서비스 지정 모델](../../specs/recipe/structure.md#스텝-서비스-지정-모델-상속-ux--저장-시-명시-확정--확정).

- **좌측 첫 행 컨트롤 구성**: `대상 서비스(스텝)` 드롭다운 + `API` 드롭다운. "서브도메인" 대신 **"대상 서비스(스텝)"** 라벨을 쓴다(비개발자가 "이 스텝이 어느 서비스를 호출하는지"로 읽히게).
- **상속 UX (미선택 허용)**: 스텝 서비스를 고르지 않으면 드롭다운 placeholder를 **"레시피 대상 서비스 상속 (사람인)"** 처럼 상속받는 서비스명과 함께 노출한다. 힌트(`form-hint`)에 **"비우면 레시피 대상 서비스를 사용합니다. 저장 시 확정됩니다."** 를 안내. 저장 시 FE가 레시피 대상 `apiSpecId`로 채워 전송하므로 저장된 스텝엔 상속 상태가 남지 않는다(structure.md 불변식).
- **다른 서비스 구분(서비스 뱃지)**: 스텝이 **레시피 대상 서비스와 다른 서비스**를 명시 선택하면, 스텝 카드 헤더에 서비스 뱃지(`.badge .badge--info`, 예: `🔀 잡코리아`)를 붙여 "이 스텝은 다른 서비스"임을 비개발자도 인지하게 한다. **레시피 대상 서비스와 같거나 상속이면 뱃지를 생략**한다(과설계 지양 — 다를 때만 노출).
- 서비스 뱃지는 스텝 카드 헤더의 스텝명 옆(타입 배지 앞)에 둔다. 접힌 스텝에서도 보이도록 헤더에 렌더.
- **접근성(뱃지)**: 서비스 뱃지의 의미는 `title`에만 의존하지 않고 **`aria-label`로 전달**한다(예: `aria-label="다른 서비스: 잡코리아"`, 못 찾음은 `aria-label="서비스 없음"`). 장식용 이모지(`🔀`/`⚠️`)는 **`aria-hidden="true"`** 로 감싸 스크린리더가 중복/무의미하게 읽지 않게 한다. (목업 span은 시각 표현용, FE는 실제 컨트롤/속성으로 구현)

#### 스텝 서비스(스펙) 못 찾음 / 비활성 경고 (신규)

스텝이 가리키는 서비스(스펙)가 **삭제되었거나 비활성(INACTIVE/DEPRECATED)** 이면 편집 화면에서 경고한다. 저장 이후 스펙이 바뀐 경우에 주로 발생한다. 참조: [execution.md 스텝 서비스 못 찾음 실패 처리](../../specs/recipe/execution.md#스텝-서비스스펙-못-찾음-실패-처리), [structure.md 검증](../../specs/recipe/structure.md#멀티-서비스-실행-규칙-확정).

- **경고 위치/톤**: 스텝 본문 상단에 `.mapping-note.mapping-note--warn` 톤으로 경고 배너를 노출. 문구: **"⚠️ 이 스텝의 서비스를 찾을 수 없습니다 — 서비스를 다시 선택하세요. 이대로 실행하면 이 스텝은 실패합니다(다른 서버로 대체하지 않음)."**
- **접근성(경고 배너)**: 서비스 재선택으로 경고가 나타났다 사라지는 동적 UI이므로 배너에 **`role="status"`(또는 `aria-live="polite"`)** 를 부여해 상태 변화가 스크린리더에 안내되게 한다(상시 존재하는 편집 경고라 `role="alert"`의 강한 인터럽트는 지양).
- **조용한 폴백 없음 안내**: 실행 시 서비스를 못 찾아도 `DEFAULT_BASE_URL`이나 레시피 대상 서비스로 말없이 대체하지 않고 **그 스텝을 실패 처리**한다는 점을 경고 문구에 명시(execution.md 정책 정합).
- **삭제된 참조 보존 패턴 정합**: 대상 서비스 드롭다운은 `useServiceOptions`의 "삭제된 참조 보존" 패턴을 따른다 — 현재 선택된(그러나 목록에 없는) 서비스는 **"(삭제됨) 이전 서비스"** 같은 톤다운 옵션으로 보존 표시하여, 값이 조용히 날아가지 않게 한다. 사용자가 새 서비스를 고르면 교체된다.
- **삭제된 참조의 저장/접근성 동작**: "(삭제됨)" 항목은 **보존 표시(현재값 유지)하되, 유효한 서비스로 재선택하기 전까지 저장 불가(유효성 에러)** 로 처리한다 — 무효 참조가 그대로 저장되는 것을 막는다. `<option disabled selected>` 는 브라우저/스크린리더에 따라 현재값으로 읽히지 않을 수 있으므로, FE는 목업의 disabled option 대신 **실제 컨트롤(Base UI Combobox 등)에서 "보존값 표시 + 무효 상태 노출(`aria-invalid`)"** 로 구현한다(목업 option은 시각 표현용).
- 스텝 카드 헤더에는 못 찾음 표시로 `.badge.badge--error`(예: `⚠️ 서비스 없음`)를 함께 붙여 접힌 상태에서도 문제 스텝을 식별하게 한다.

#### 실행 진행 / 히스토리에서의 서비스 뱃지 (표기 방침 — 검토 결과)

멀티 서비스 레시피의 실행 진행(`chat.html`의 `progress`/`plan-progress`)·히스토리 상세에서 스텝별 서비스를 뱃지로 구분할지 검토했다.

- **방침(과설계 지양)**: **레시피가 실제로 2개 이상 서비스를 호출할 때만** 진행/히스토리 스텝 줄에 서비스 뱃지(`.badge.badge--info`, 편집 화면과 동일 톤)를 붙인다. 단일 서비스 레시피는 뱃지를 **생략**한다(모든 스텝이 같은 서비스라 중복 노이즈).
- 판정 근거는 실행 스냅샷의 `services` 엔트리 수(2개+면 멀티)로 한다([execution.md 실행 스냅샷 계약](../../specs/recipe/execution.md#실행-스냅샷-계약-servicesresolvedsteps)).
- 이 방침은 편집 화면(recipe-editor)의 스텝 헤더 뱃지 규칙과 톤을 맞춘다. 진행/히스토리 HTML의 실제 뱃지 렌더 반영은 해당 화면(chat/history) 디자인 작업 범위이며, 본 문서에서는 규칙만 확정한다.

#### 요청 필드 매핑 (2단계 — 명세 기반 자동 나열 + 레시피 기본값)

- **자동 나열**: API를 고르면 그 명세(`operationJson`, `$ref` 인라인됨)에서 **경로/쿼리 파라미터 + 요청 바디 필드**가 매핑 테이블에 자동으로 채워진다. 참조: [authoring.md ③ 요청 필드 매핑](../../specs/recipe/authoring.md#api-타입--요청-필드-매핑).
- **필드명 고정**: 자동 생성된 필드명은 스키마가 원천이라 작성자가 바꿀 수 없다(`mapping-table__field`). 필수 필드는 `*`(`mapping-table__required`)로 표시.
- **테이블 열**: 필드 | 값 소스(드롭다운) | 매핑 값(드롭다운/입력) | **레시피 기본값**(신규 열). 값 소스 4종: 이전 스텝 결과 / 사용자 입력 / 직접 입력 / AI 생성.
- **레시피 기본값 열**: 각 매핑 필드에 "이 레시피에서의 기본값"을 붙일 수 있다(비우면 없음). 실행 시 값 우선순위 **사용자 실행 입력 > 레시피 기본값**을 힌트로 안내.
- **매핑 값 vs 레시피 기본값 구분**: `매핑 값`은 실행 시 실제로 넣는 값(값 소스로 결정)이고, `레시피 기본값`은 매핑 값이 비었을 때만 쓰는 폴백값이다. 즉 **매핑 값이 우선, 기본값은 폴백**. 컬럼 헤더 근처 안내 문구로 이 구분을 노출한다.

#### 요청 헤더 매핑 (2단계 — 신규 서브섹션)

- 요청 필드 매핑과 **동일한 테이블 패턴**: 헤더 | 값 소스 | 매핑 값 | 레시피 기본값.
- 선택한 엔드포인트에 헤더 정의가 있으면 **헤더 이름을 자동 제시**(고정), 없으면 [+ 헤더 매핑 추가]로 수동.
- 섹션 상단에 톤다운 안내(`mapping-note`): **인증 key 등 민감 헤더는 값 소스를 "사용자 입력"으로 두는 것을 권장**(직접 입력 고정값은 레시피 정의에 그대로 저장됨). 또한 **인증/식별 헤더에는 "AI 생성" 값 소스를 권장하지 않는다**. 참조: [authoring.md 요청 헤더 매핑](../../specs/recipe/authoring.md#api-타입--요청-헤더-매핑), [execution.md 요청 헤더 주입](../../specs/recipe/execution.md#요청-헤더-주입-2단계).

#### 명세 없음 폴백 (구 데이터 / 수동 최소 등록)

- `operationJson`이 없거나 파싱 실패한 엔드포인트는 자동 나열이 불가하므로, **빈 상태(`empty-state`) + 경고 안내(`mapping-note--warn`) + [+ 필드 매핑 추가]/[+ 헤더 매핑 추가]** 로 폴백해 편집이 막히지 않게 한다.
- 안내 문구: "이 API는 상세 스키마(operationJson)가 없어 필드를 자동으로 나열할 수 없습니다. 매핑을 직접 추가하세요."
- 폴백에서 수동 추가한 필드/헤더는 스키마 원천이 없어 필수(*) 표시가 없으며, 필수 검증 대상이 아니다(작성자 책임).
- 기존 매핑 보존 원칙(자동 나열이 기존 편집을 덮어쓰지 않음)은 기획 정본을 따른다([authoring.md 자동 필드 데이터 출처와 폴백](../../specs/recipe/authoring.md#자동-필드-데이터-출처와-폴백)).

### 표시명(label) 폴백 체인 (④ 결과 정의 + 스텝 표시명 공통)

| 대상 | 폴백 우선순위 |
|------|--------------|
| 스텝 표시명 | (1) 스텝 label → (2) 엔드포인트 summary → (3) method + path |
| 결과키 표시명 | (1) 결과 정의 label → (2) 원본 key 그대로 |

- 표시명 입력은 모두 선택 필드 — 비우면 위 순서로 자동 폴백하여 표기가 깨지지 않음
- 중첩/배열 key(`items[0].price`)는 label 없으면 경로 그대로, 값이 null이면 "값 없음"으로 표기
- 참조 기획: [authoring.md ④ 결과 정의](../../specs/recipe/authoring.md#-결과-정의), [response-guide.md 표시명 폴백 체인](../../specs/common/response-guide.md#표시명label-폴백-체인)

### ⑤ 결과 메시지 템플릿 (문법 + 도움말 툴팁)

결과 메시지 템플릿은 **마크다운 + Handlebars** 문법으로 작성한다. textarea 라벨 바로 옆에 도움말 툴팁(ⓘ, 기존 `.tooltip` 컴포넌트 재사용)을 두어 작성 위치 근처에서 문법을 안내한다.

- **툴팁 내용**(요약): 값 `{{key}}` / 사용자 입력 `{{userInput.x}}` / 반복 `{{#each items}}...{{/each}}` / 조건 `{{#if x}}...{{/if}}` / 헬퍼 `{{formatNumber v}}`·`{{limit items 20}}`·`{{default v "-"}}` / 마크다운 표 `| |`. 쓸 수 있는 값은 ④ 결과 정의 + ② 사용자 입력.
- **placeholder**: 마크다운+변수 예시(예: `**{{ownerName}}**님의 잔액은 {{formatNumber balance}}원입니다.`)
- **힌트 문구**: "마크다운 + Handlebars 문법 지원(반복·조건·표). 사용 가능한 변수: ④ 결과 정의 + ② 사용자 입력. 미입력 시 결과값을 자동 요약합니다." (기존 "AI가 자동 요약"에서 정정 — AI 요약은 후속)
- 목록 조회 레시피는 마크다운 표/리스트로 결과를 표현한다(배열 값 + `{{#each}}`).
- 참조 기획: [authoring.md ⑤ 결과 메시지 템플릿](../../specs/recipe/authoring.md#-결과-메시지-템플릿)

### Case 4: 스텝 편집 (스크립트 타입)

- 사용할 변수: 체크박스 목록
- 코드 에디터: textarea (추후 Monaco)
- 출력 변수: 변수명 + 설명 테이블

### Case 5: 유효성 에러

- 저장 클릭 후 에러 목록 표시
- 각 에러에 해당 필드 하이라이트 (빨간 border)
- 에러 요약 alert (상단)

### Case 7: 목록 — 다중 필터 / 정렬 / 권한 게이팅

목록 화면 UX 개선 (기획: [recipe-editor.md 검색/필터/정렬](../../specs/pages/recipe-editor.md#검색--필터--정렬)).

- **다중 선택 필터**: 서비스 / 범위 / 태그 축별 체크박스 드롭다운. **빈 선택 = 전체**(거르지 않음).
  - 선택 항목은 **필터 칩**으로 노출, 칩의 개별 `✕`로 하나씩 해제.
  - [필터 초기화] 버튼 + "활성 필터 N개" 요약 문구.
  - 서비스 필터는 메타 대상 서비스 기준(스텝 내부 호출 서비스로는 안 거름).
- **정렬**: 드롭다운(최근 사용순 기본 / 사용 많은순 / 이름순 / 최근 수정순) + 방향 토글(▲오름 / ▼내림).
- **목록 행**:
  - 범위 배지: 🌐 공통(badge--info) / 🔒 개인(badge--neutral) — 서로 다른 색.
  - 이름 + 아래 설명 1줄(말줄임, 없으면 "(설명 없음)" 톤다운).
  - `validationStatus=INVALID`면 ⚠️ 경고 아이콘 + 사유 툴팁.
  - 최근 사용 상대시간(예: "2시간 전", 없으면 "미사용").
  - hover 시 액션 노출: ✏️ 편집 / ⧉ 복제 / 🗑️ 삭제.
  - 결과 카운트 "총 N개".
- **권한 게이팅** (일반 사용자 시점): 공통 레시피 행은 편집·삭제 숨김(복제만), 본인 개인 행은 전체 액션. (관리자 시점은 전체 — Case 1이 그 예시)
  - 판정 근거: 응답 `canEdit`([auth.md 권한 힌트](../../specs/common/auth.md#레시피-권한-매트릭스)). UX 힌트일 뿐 실제 권한은 서버가 강제.

### Case 8: 목록 — 빈 상태 / 필터 결과 없음

- **레시피 0개**: empty-state + [+ 레시피 만들기] CTA.
- **필터 결과 없음**: 필터는 적용됐으나 매칭 0건 → 안내 + [필터 초기화] 유도.

### Case 9: 목록 — 삭제 확인 모달

- `window.confirm` 금지, ConfirmModal 사용([system.html](../shared/system.html)).
- 안내: "실행 히스토리는 유지됩니다. 레시피 정의는 되돌릴 수 없습니다."
- [취소] / [삭제](danger).

### Case 10: 목록 — 반응형(Tablet 이하) 카드 폴백

- `< 1024px`에서 data-table을 숨기고 카드형 목록으로 전환.
- 각 카드: 범위 배지 + 이름 + 설명 + 서비스/태그/상대시간 + 액션.

### Case 11: 편집 — 버전 기록 drawer

버전 관리 UI (기획: [versioning.md](../../specs/recipe/versioning.md), [recipe-editor.md 버전 기록](../../specs/pages/recipe-editor.md#버전-기록)).

- 헤더 [🕘 버전 기록 vN] 배지 버튼 → 우측 slide-in drawer.
- 목록 최신순, 현재 버전은 ● 표시 + "현재" 배지(미리보기/복원 버튼 없음).
- 각 과거 버전: `vN` + 상대시간 + [미리보기] [복원].
- 하단 [더 보기](커서 페이징).
- 빈 상태(v1만 = 이력 없음): "아직 수정 이력이 없습니다".

### Case 12: 편집 — 버전 미리보기 모달

- 읽기전용, 편집 폼과 동일 렌더(메타 / 스텝 / 결과정의 / 결과 템플릿).
- 상단: `versionNo` + `createdAt`.
- 푸터: [닫기] / [이 버전으로 복원](읽기 전용 모드에선 복원 숨김).

### Case 13: 편집 — 복원 확인 모달 + 토스트

- 안내: "vX 내용으로 새 버전(vN+1)을 만듭니다. 현재 내용은 vN으로 보관되어 안전합니다. 되돌리기도 이력에 남습니다."
- 복원 결과가 INVALID일 수 있음 경고(스펙 변경으로 무효화 가능, 복원 자체는 성공).
- 복원 성공 시 토스트 + 헤더 버전 배지 vN+1로 갱신.

### Case 14: 편집 — 읽기 전용 모드 (공통 × non-admin)

- 상단 안내 배너 "공통 레시피 · 읽기 전용" + [개인 사본으로 복제].
- 모든 입력 disabled, [저장]/[삭제] 숨김.
- [버전 기록] 진입/미리보기는 가능하되 **[복원] 버튼만 숨김**(`canEdit=false`).

## 반응형

- Desktop 우선 (편집 페이지는 넓은 화면 필수)
- 목록 화면은 `< 1024px`에서 테이블 → 카드형 폴백(Case 10)
- 편집 페이지 최소 너비: 1024px
- Tablet: 스크롤로 사용 가능하지만 최적화하지 않음

## 접근성

- form 필드에 label 연결
- 드래그앤드롭에 키보드 대안 (위/아래 버튼으로 스텝 순서 변경)
- 유효성 에러 시 aria-invalid + 에러 메시지 연결
- 오버레이형 UI(버전 기록 drawer, 버전 미리보기 모달, 복원 확인 모달, 작성 도움말 툴팁) 공통 규칙: ESC/바깥 클릭 닫기, 열릴 때 내부 첫 포커스 요소로 이동, 닫으면 트리거로 포커스 복귀, 트리거 `aria-expanded` 동기화. 이 동작은 FE가 직접 구현하지 않고 **앱 공통 래퍼(`AppDrawer`/`AppModal`/`ConfirmModal`/`AppTooltip`, 모두 Base UI 기반)가 담당**한다([ui-patterns.md 오버레이 구현 규칙](../../specs/common/ui-patterns.md#오버레이-구현-규칙-base-ui-래퍼로만)). 중첩 오버레이(드로어 안 미리보기/복원 확인)는 부모 트리 안에 렌더해 Base UI가 top-most를 인식하게 한다.
